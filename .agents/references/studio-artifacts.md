# Исходники документов и материалов Studio

Этот контракт предназначен для агентов. Инструкция Workspace объясняет работу с бизнесом; схемы и расположение файлов хранятся здесь.

## Владение

Существенные факты, требования и решения доступны в содержимом страниц Studio. Метаданные хранят идентификаторы. Внутренние ссылки ведут только на зарегистрированную историю Storybook или якорь. Таблицы, аргументы и условия нельзя прятать в незарегистрированных Markdown, CSV или YAML. Внешние первоисточники и видимые изображения допустимы. Полные скрытые копии документов не создаются; нужные сведения остаются на странице, повторы удаляются.

Общие документы: `apps/studio/workspace/<artifact>/{singlepage,startup}.md`. Активный слой определяется по `.agents/contracts/inheritance.md`. У продукта одна папка `products/<layer>/<product-id>/`; в ней его документы, компоненты и ресурсы. Общий код отображения находится в `workspace/utils/`.

Каталог `products/<layer>/catalog.yaml` использует актуальную схему v2. Все его пути разрешаются внутри соответствующего `products/<layer>/`. Продукт имеет постоянный `id`, название и ссылки `product`, `audience`, `competitors`, `semantics`, `economics`, `sales`. Для создания документов запись Ecommerce не требуется.

`customer_segments` описания и ID сегментов в `sales.yaml` должны совпадать. У каждого типа документа фиксированы H2 из шаблона, одинаковые для всех продуктов. Исследования находятся в видимых аудитории, конкурентах и семантике.

## Материалы

`website` и `marketing_creative` указывают на краткие документы бизнес-контекста. `sections` группирует страницы материала. У страницы один `source`: Markdown для бизнес-контекста, React/HTML для готовой статьи или другого макета. Поля `id`, `title` и `children` задают блоки и порядок чтения.

Сайт объединяет бизнес-контекст и макет посадочной в одной истории. Презентация указывает на React-компонент через `presentation`; данные слайдов находятся в этом компоненте или его собственных импортируемых файлах. Отдельного поля каталога для данных презентации нет. Изменения текста сайта, слайдов и рекламы вносятся в их исходники, без параллельного текста в Markdown.

Каждая статья — один узел `sections.articles.pages` и одна история Storybook. Её корневая карточка содержит `audience`, `semantic_cluster`, `goal`, а `children` — блоки SEO, статьи, видео, постов и результатов. Файлы можно разделять для редактирования; навигация Storybook ведёт к комплекту статьи целиком.

Созданные продукты и материалы регистрируются в каталоге. После изменения проверить структуру, отсутствие потерянных ссылок, отображение и выгрузку изменённого материала. Поддерживается одна текущая форма данных; изменение структуры включает приведение используемых файлов к ней.

## Экспорт и ресурсы

Markdown-документы скачиваются в Markdown и HTML. React-макеты остаются редактируемыми исходниками; экспорт сохраняет их отображение. Общие средства экспорта — `workspace/utils/media/`: ArtifactFrame для PNG, средства презентации для PDF, MotionPreview для видео. Кнопки экспорта находятся вне самого макета.

Логотип, шрифты и общие изображения принадлежат дизайну активного слоя. Рекламный материал или слайд ссылается на них, сохраняя свой текст и композицию. История изменений — Git; служебные отметки согласований и миграционные архивы в бизнес-документах не хранятся.
