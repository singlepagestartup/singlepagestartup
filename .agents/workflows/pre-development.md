# Подготовка проекта

Процесс используется для команды `singlepagestartup`, `/singlepagestartup` и обычного запроса работать с проектом в Studio.

## Выбор работы

Передать выбор пользователя общей команде:

```bash
npm run singlepagestartup -- --section semantics --product <product-id>
```

Разделы: `brief`, `products`, `competitors`, `semantics`, `strategy`, `brand`, `design`, `materials`. Это рекомендуемая последовательность; параметр `--section` выбирает любой раздел. Без параметров продолжается сохранённая работа. `--skip` отмечает пропуск, `--complete` — подготовленный результат; оба переводят дальше. `--next` переходит дальше без отметки завершения.

Для продукта использовать ID каталога. Если контекст не определяет продукт, а их несколько, уточнить выбор. При пустом каталоге создать описание по имеющимся сведениям и зарегистрировать свободный постоянный ID. Запись Ecommerce на этом этапе не требуется.

Активный слой определяется по репозиторию: фреймворк работает в `singlepage`, дочерний проект — в `startup`. Следовать `.agents/contracts/inheritance.md`. Исходные данные чужого бизнеса не заполняют пробелы клиента. Позиция работы хранится в `workspace/utils/pre-development/<layer>.yaml`.

## Выполнение

1. Прочитать текущий документ, роль, подходящий шаблон и необходимые источники. Загружать материалы выбранного продукта и задачи.
2. Следовать `.agents/contracts/research-ownership.md`. Самостоятельно собрать доступные факты, проверить предложения конкурентов, поисковые данные или функции продукта. При недоступном API использовать подходящий браузерный интерфейс; наличие входа и доступа проверять, а не предполагать.
3. Сформулировать результат: описание, сравнение, вывод, решение, запросы или материал. В бизнес-документе не оставлять поручения оператору вместо исследования. У пользователя спрашивать только недоступный факт, решение или действие для доступа; независимую работу продолжать.
4. Сохранить сведения в ответственном документе. Изменившийся факт исправить в затронутых материалах в рамках текущего поручения; посторонние документы не переписывать.
5. Проверить результат целиком: смысл, факты, источники, ссылки и отображение. Структурная диагностика `npm run singlepagestartup:pipeline:check -- --format text` помогает найти ошибки файлов. Она не заменяет исследование.
6. Кратко сообщить, что получилось и где это посмотреть. Отметить результат подготовленным после выполнения запрошенной работы. Выбранный раздел меняется по явному переходу, пропуску или завершению, а не по состоянию соседних документов.

## Разделы и ответственность

| Раздел     | Роль                                          | Результат                                                                  |
| ---------- | --------------------------------------------- | -------------------------------------------------------------------------- |
| Бриф       | Аккаунт-менеджер                              | Исходные факты, цели и ограничения из разговора и материалов               |
| Продукты   | Бизнес-аналитик                               | Понятное описание, экономика и процесс продаж каждого продукта             |
| Конкуренты | Исследователь рынка                           | Реальное сравнение предложений и сайтов, выводы об аудитории и конкуренции |
| Семантика  | Исследователь рынка                           | Запросы с источниками, измерения, группы, назначения страниц и приоритеты  |
| Стратегия  | Стратег                                       | Выбранные аудитории, роли продуктов и способы достижения целей             |
| Бренд      | Стратег по коммуникации                       | Общий смысл, восприятие, голос и доказательства обещаний                   |
| Дизайн     | Бренд-дизайнер                                | Визуальные правила и примеры, применимые к продуктам                       |
| Материалы  | Веб-дизайнер и подходящий специалист контента | Посадочная, презентация, рекламные креативы и статьи                       |

Описание продукта создаётся по `templates/product.md`; аудитория, конкуренты, семантика, экономика и продажи — отдельные документы. Методы исследования — в `references/product-research.md`. Сведения хранятся в Workspace, инструкции и схемы — в `.agents`.

## Объём и доказательства

Рекомендуется основной результат в 600–1 000 слов. Это ориентир для чтения, не предел: объяснение, исследование или комплект статьи может быть длиннее. Подробные исходные данные показывать в соответствующей странице Studio. Внутренние ссылки ведут на зарегистрированные истории и якоря. Не создавать скрытых документов, от которых зависят решения.

Наблюдения, расчёты, гипотезы и планы различать по смыслу. Неизвестная частотность не становится нулём; локальный макет не означает публикацию; запланированная функция не является доступной. Существенное ограничение сообщить рядом с выводом, сохраняя всё, что удалось установить.

## Структура документов

Сохранять H2 и порядок из канонического шаблона. Проверять все продукты. Веб-профили и руководства документов используют ту же структуру; после изменения шаблона обновить их и выполнить локальную генерацию.

## Материалы

Следовать `references/materials.md` и `references/studio-artifacts.md`. Предложение принадлежит описанию продукта, путь клиента — продажам. Каждый материал относится к существующим сегменту и этапу CJM. Прочитать весь контекст продукта и проекта; провести человека от потребности через аргументы и ответы на возражения к действию из продаж. Сайт, презентация, реклама и статья сохраняют одно предложение и условия. При изменении CJM обновить затронутые материалы в текущей задаче; автоматических возвратов к прошлым этапам нет.

Сайт, презентация и реклама редактируются сразу в исходниках макетов. Для статей применять `references/seo-articles.md`: один читатель, один вопрос, один следующий шаг по CJM; выбор темы опирается на спрос и изученную выдачу. У статьи одна история со всеми форматами и обложками. Создание готового рекламного материала включает сам креатив, а не только задание на него.

## Проверка по запросу

Проверка по запросу — `contracts/document-confirmation.md`. История — Git. Поддерживается текущее состояние документов и схем, без метаданных автоматического согласования.

## Редактура текста

Перед сохранением и ответом пользователю выполнить `.agents/contracts/editorial-pass.md`: убрать пустые формулировки, раскрыть конкретные возможности и довести выводы до ответа на вопрос читателя.
