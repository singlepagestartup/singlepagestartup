## Context

The AI Chat variants require the existing SPS model readers and explicit client
view props. Additional local readers duplicated Provider ownership, and broad
prop forwarding exposed SDK functions at the RSC boundary. The corrected flow
has a recorded typecheck pass, 25 passing tests and browser verification for
Help, account settings, document threads and ordinary threads in
[component-wrapper-validation.json](../../processes/singlepagestartup/ai-chat-production-evidence/component-wrapper-validation.json).

## Findings

### 1. Template ownership needs an implementation entry point

- Surface: shared
- Type: command contract
- Impact: reliability and portability
- Evidence: The frontend role lists the variant files and SDK requirements, but
  its original boundary section does not assign loading and Provider ownership
  to the applicable shared template. The session includes extra local loaders
  and repeated Providers. CRM Form
  [support-ai-chat/index.tsx](../../../../libs/modules/crm/models/form/frontend/component/src/lib/singlepage/support-ai-chat/index.tsx)
  supplies the concrete shared-parent pattern.
- Root cause: The general implementation entry points lack a specific template
  reuse requirement for frontend work.
- Recommended fix: The shared frontend component contract assigns ownership and
  is required by both implementation workflows and the frontend role.

### 2. RSC review must trace runtime props

- Surface: shared
- Type: validation gap
- Impact: reliability
- Evidence: The original frontend role already prohibits a broad prop spread,
  while the general PR-review source mentions client/server boundaries without
  identifying reader implementation props. The shared default parent supplies
  `clientApi`, `serverApi` and `Provider`; its server reader removes only
  `Component`, `Skeleton` and `api` before rendering the view. A view's declared
  interface does not remove the remaining runtime fields.
- Root cause: Interface inspection and type checks do not establish which
  function-bearing objects reach the client view.
- Recommended fix: Require explicit public UI props, JSX slots and tracing of
  callback producers and consumers. Validate the public component through its
  real reader and inspect the affected browser route. The existing
  [support form regression test](../../../../libs/modules/crm/models/form/frontend/component/src/lib/singlepage/support-ai-chat/Component.spec.tsx)
  checks one Provider and excludes SDK bindings from client view props.
