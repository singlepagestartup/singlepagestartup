## Context

The SinglePageStartup pre-development workflow collected strategy facts over a
long interview. After almost every operator correction, the strategy owner was
rerun against the existing strategy file. The resulting living artifact grew to
794 lines, including 182 non-empty lines in its decision-status section, and
repeated the same
budget, support, licensing, readiness, and evidence boundaries across status,
commercial choice, experiment, measurement, risks, invalidations, and profile
handoff prose. The operator approved the decisions but rejected the document
shape and requested a process repair followed by a fresh strategy generation.

## Findings

### 1. Strategy regeneration became append-oriented reconciliation

- Surface: shared
- Type: command contract
- Impact: reliability and maintainability
- Evidence: `.agents/contracts/artifact-lifecycle.md` requires one current
  decision per topic and replacement of stale content, while
  `apps/studio/workspace/strategy/singlepage.md` retained chronological
  corrections and repeated current facts. The strategist was rerun after nearly
  every operator answer instead of after a stable input batch.
- Root cause: the Decide contract says to update the strategy but does not state
  that a full strategy rerun must ignore and replace the prior body. The role
  therefore optimized for preserving context rather than producing a clean
  current projection.
- Recommended fix: define strategy generation and regeneration as replacement
  from approved upstream artifacts. During fact collection, update only the
  brief, evidence register, decision profile, and owning operating artifact;
  run the strategist after the input batch is stable.

### 2. Strategy content ownership is not strict enough

- Surface: shared
- Type: artifact structure
- Impact: maintainability and portability
- Evidence: `.agents/templates/strategy.md` defines four compact sections, but
  the generated file added approval chronology, profile disposition, evidence
  implications, downstream invalidations, and handoff instructions. These
  concerns already belong to Git history, the evidence register, decision
  profile, workflow coordinator, or final handoff.
- Root cause: neither the strategist role nor the template assigns each strategy
  decision to one canonical section or forbids workflow metadata inside the
  artifact.
- Recommended fix: use exactly four top-level sections, a compact commercial
  choice table, one experiment table, and one risks/evidence table. Prohibit
  chronological interview logs, profile disposition, invalidation logs, and
  coordinator handoff prose in the strategy source.

### 3. Validation checks structure but not strategy usability

- Surface: shared
- Type: validation gap
- Impact: reliability
- Evidence: `tools/singlepagestartup/agents/validate.ts` validates adapters,
  roles, durable state, and decision-profile wiring, but it does not validate
  strategy length, heading shape, repeated paragraphs, or misplaced workflow
  metadata. Formal validation passed while the strategy was unusably repetitive.
- Root cause: the quality gate has no executable artifact-specific constraints.
- Recommended fix: validate non-empty strategy sources for exact required
  headings, heading order, bounded total lines and words, compact decision
  status, no duplicate long paragraphs, and absence of profile, invalidation,
  chronology, or handoff sections.

## Quick Wins

- Add an explicit replace-from-upstream rule to the Decide workflow and
  strategist role.
- Replace the strategy template with canonical tables and strict section homes.
- Add strategy artifact checks to the shared agent validator.

## Structural Improvements

- Treat living artifacts as current projections, while Git and the evidence
  register retain history and provenance.
- Separate fact collection from professional artifact generation: batch stable
  operator facts before invoking downstream owners.
- Make semantic compactness a stage gate rather than an optional writing style.
