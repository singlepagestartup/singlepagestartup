# Knowledge: результат реализации

Source хранит полный текст знания и пользовательские пояснения; Chunk является производным индексом. Document, Edit Suggestion и Profile → Documents удалены. Профиль, сообщения и skills связаны с Source через relations. Переноса данных и встроенного отката нет.

Актуальность индекса определяется по `contentHash` и `indexedContentHash`. Успешная атомарная публикация chunks сохраняет `lastIndexedAt` обычным CRUD; `updatedAt` следует правилам фреймворка. Source имеет стандартные поля SPS, заголовок, `content`, необязательное `description` и эти три поля индексации.

Несколько Files составляют один Source. PDF анализируется по каждой странице; изображения описываются; видео объединяет кадры с шагом в одну секунду и транскрипцию, аудио сохраняет временные отметки. Изменение файловых relations или самого общего File пересобирает все затронутые Sources по их текущим вложениям. Старый автоматический текст и chunks очищаются до анализа. Пользовательский раздел копируется сервисом без изменения. Ошибка сохраняет пользовательский текст и доступные вложения; устаревшая сборка не публикуется.

Чат читает Source порциями и применяет явную правку напрямую. Инструмент сверяет хеш прочитанного текста при сохранении. Файловые операции проверяют исходный набор вложений и сохраняют порядок при замене. Telegram также читает `content` и сохраняет описания файлов при редактировании пользовательских пояснений. Unlink удаляет только профильную relation; глобальное удаление Source сохраняет Files.

В локальном чате «Knowledge Source · урок 13 · проверка» создан AI-профиль и один Source с предоставленными PDF и TXT. Пройдены вопросы по фактам, описание фотографии, сравнение противоречащих сведений PDF и TXT, правка в чате, замена TXT, отсоединение PDF и последнего TXT. Пользовательские заметки сохранились. Итоговый Source снова содержит исходные PDF и TXT, 45 chunks и совпадающие хеши. Исходные учебные файлы не изменены и не входят в Git. Обновление заголовка видно во втором открытом интерфейсе без перезагрузки и без новой индексации.

Production-сборка Host и прямые TypeScript-проверки Knowledge, Social, RBAC и Host проходят. Knowledge unit и шесть DB-backed проверок проходят; DB проверяет изоляцию scope, свежесть индекса, атомарность, общий File, конкурентное изменение вложений и удаление Source. Проверки связанных API, RBAC, Social, Shared Utils, OpenRouter, Telegram и AI Chat прошли; подробные результаты находятся в плане. Нативные Poppler/FFmpeg проверены на PDF, изображении, видео с речью, видео без звука и аудио. Для предоставленного PDF и чата использованы реальные провайдеры; отдельно прошла реальная транскрипция OpenRouter.

Studio inventory и validate возвращают exit 0. Четыре незакрытых согласования бизнес-документов сохраняются как отдельные пробелы pre-development. Aggregate Nx `tsc:build` ограничен существующим циклом зависимостей и разрешением wildcard aliases; прямые проверки типов и production-сборка проходят.

Локальная конфигурация API задаёт команды Poppler через `KNOWLEDGE_PDF_INFO_COMMAND` и `KNOWLEDGE_PDF_RENDER_COMMAND`; в Docker установлены Poppler и FFmpeg. Учётные данные, ключи, загруженные материалы и локальные журналы не входят в коммит. Независимые изменения MCP, деплоя и бизнес-документов остаются в рабочем каталоге.
