## Incident Log

<!-- incident-count: 3 -->

### Incident 1 — повторный импорт метаданных страниц

- **Occurrences**: 1
- **Stage**: данные Host Page
- **Symptom**: при повторном seed появлялись лишние связи SEO.
- **Root Cause**: отдельные записи Metadata для двух страниц требовали дополнительных связей с нестабильной идентичностью при импорте.
- **Fix**: страницы ссылаются на собственные локализованные поля SEO через маски. Повторный seed тех же 16 снимков в отдельной PostgreSQL сохранил записи и связи.
- **Reusable Pattern**: проверять второй импорт и перечитывать результат через Host findByUrl и SEO на обоих языках.

### Incident 2 — поиск учитывал только видимую страницу чатов

- **Occurrences**: 1
- **Stage**: проверка Social Chat
- **Symptom**: чат на более поздней странице отсутствовал в поиске.
- **Root Cause**: клиент фильтровал уже загруженную страницу. Поиск по сырому содержимому поля title также захватывал скрытые переводы и ключи JSON.
- **Fix**: сервер ищет по отображаемому названию в пределах членства и прав пользователя до выбора страницы. Тест охватывает 111 чатов, старые строковые заголовки и чат без названия.
- **Reusable Pattern**: проверять поиск совпадением за пределами первой страницы на языке интерфейса.

### Incident 3 — статус отменённого заказа

- **Occurrences**: 1
- **Stage**: проверка карточки заказа
- **Symptom**: покупатель мог видеть ожидание оплаты после отмены.
- **Root Cause**: карточка всегда отдавала предпочтение состоянию работы.
- **Fix**: карточка использует этап исполнения только у активного заказа. Отмену и ошибку оплаты показывает по состоянию самого заказа.
- **Reusable Pattern**: отдельно проверять терминальное состояние заказа при устаревшем этапе работы.

## Summary

Ветка `codex/issue-442-profile-orders-chats`. [PR #444](https://github.com/singlepagestartup/singlepagestartup/pull/444).

Покупатель открыл заказ из меню, увидел позиции, количество и статус. В двух сессиях Chrome покупатель и продавец прочитали сообщения друг друга без перезагрузки. Покупатель запросил правку первого превью и принял вторую версию. На уточнение о заголовке и оплате ответил штатный обработчик агента через локальный тестовый транспорт модели. Платёж dummy на 25 ₽ завершился, покупатель скачал оригинал и PDF-чек. После повторного входа сохранились статус заказа и переписка. Обычный чат проверен отдельно между двумя участниками. Проверены мобильный профиль, чужой заказ, неверный UUID и старый заказ без обсуждения.

Прошли сборки Host и Studio Storybook, TypeScript Host и Studio, 60 целевых тестов RBAC, 18 тестов Host SEO, интеграционная проверка Ecommerce с PostgreSQL и повторный seed 16 записей на отдельной базе. Проверка зависимостей обработала 16 861 файл без нарушений. Линтер завершился с шестью существующими предупреждениями в Host. Проверка циклов Studio прошла. Отдельный тест имён импортов сообщает о четырёх существующих местах в CRM и Social.

## Правки после проверки покупателем

Оба экрана используют вариант Ecommerce Product `customer-order-line`. В списке и в отдельном заказе покупатель видит обложку, количество, стоимость позиции и переход на товар. В карточке заказа доступны сохранённые сведения о доставке и платеже, почта и чек. Для завершённой электронной выдачи указан файл в чате заказа. Переписка открывается сразу под карточкой. Всплывающие уведомления Host и Studio используют общий компонент по предоставленному образцу.

В локальной базе у демонстрационного товара не было изображения. Через кабинет тестового продавца ему добавили публичную иллюстрацию из Studio. В Chrome на ширинах 1280 и 375 px проверены изображение, переход на страницу этого товара, данные покупателя, скачивание PDF и отказ в доступе другому пользователю. На работающем Host проверены уведомления об успехе и ошибке. В проверке сервиса отдельно учтены удалённые позиции, доставка по адресу и общий платёж за несколько заказов.

## Навигация по товару и обсуждениям

Вся строка опубликованного товара открывает страницу каталога. Обложка и название стоят слева, количество и сумма позиции справа. По итогам проверки восстановлена навигация из PR #422. При выборе чата с несколькими тредами их список занимает левую панель. Чат с одним тредом сразу открывает сообщения. Встроенная переписка заказа остаётся в контексте заказа.

В локальной базе у покупателя есть рабочий чат заказа и обычный чат с администратором. В мобильном Chrome покупатель создал второе обсуждение в обычном чате и отправил сообщение. В открытом окне на десктопе оно появилось без перезагрузки. Сервер вернул его при чтении с правами участника-администратора.
