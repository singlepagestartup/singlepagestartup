## Summary

Studio displays models through local Component/index entries and merged singlepage/startup variant maps. All 61 production models across 15 modules are represented; Telegram is excluded. Pages compose model views directly, with local fixtures and Storybook Controls for display states.

The branch also retains the Knowledge Source, file orchestration, MCP configuration and Host fixes described below. This Studio simplification changes no production libraries.

- Compose cross-model views through public model entries and explicit variants across Blog, CRM, Ecommerce, Host, RBAC, Social and Website Builder. - Keep every AI Chat screen in a concrete Host Page. Host Layout `ai-chat-header` owns one page frame and the Website Builder header. Pages supply Profile Select and Subject Account slots. Header composes Logotype, Buttons Array and Button models directly without higher-module imports.
- Keep the project overview, sidebar and mobile drawer in Social Profile. Account renders the supplied user Profile directly. New thread remains a visual creation process with name, one agent, Create and Cancel; submit creates no records.
- Simplify Host inspection to Page, Layout, Widget and Metadata examples. Remove join editors, access-link fixtures and relation management from Host, RBAC and Ecommerce examples. Product forms receive an Attribute view slot.
- Keep Studio implementations, fixtures, generated copy and assets local. Production prototype imports/routes/styles are removed from this branch; production transfer remains a separate step.
- Retain Knowledge Source content/attachments, paginated tools, Unicode response budgets and scoped editing. File Storage remains independent of Knowledge; Knowledge orchestrates attachment changes and preserves user context.
- Retain Bun MCP client generation, Host locale middleware fixes and layered Studio Design examples.
