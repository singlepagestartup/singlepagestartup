## Summary

Покупатель может вернуть товары из неоплаченного заказа в корзину, выбрать способ оплаты и оформить заказ заново. Перед заменой интерфейс просит подтвердить удаление текущих позиций. Корзина, история покупок и роли принадлежат RBAC Subject.

## Changes

- `POST /api/rbac/subjects/:id/ecommerce-module/orders/:orderId/repeat` проверяет владельца и статус оплаты. Новая корзина получает товары и количества исходного заказа. Для оформления используются текущие цены.
- Сервер готовит платёж и привязывает заказы в одной транзакции. Ошибка во время подготовки откатывает её. При тайм-ауте провайдера попытка остаётся в истории, а изменения корзины из другой вкладки сохраняются.
- Позднее подтверждение платежа возвращает в обработку заказ, который система отменила из-за ошибки оплаты. Очистка истории сохраняет такие заказы. Успешную покупку обрабатывает обычный механизм выдачи ролей.
- Если покупатель оплатил исходную и повторную подписку на один продукт, оба счёта и начисления сохраняются. Продлевается одна подписка. Для Stripe лишнее продление отключается в конце оплаченного периода. Уже оплаченные периоды могут совпадать по времени.
- Старый общий счёт можно открыть при выборе всех входящих в него заказов. Для новых подписок каждый заказ получает отдельный платёж. Если оформление выдаёт несколько ссылок, они остаются на экране после обновления корзины.

## Notes

Первоначальный счёт может быть оплачен после создания новой корзины. У старых отменённых заказов без признака причины отмены требуется ручная сверка. Если два старых договора Stripe одновременно покрывают сторонние заказы, их также нужно сверить вручную.

### Downstream migration

Перед обновлением приложения примените миграцию Ecommerce Order штатной командой `npx nx run api:db:migrate` и загрузите новое разрешение RBAC штатным seed. В переопределённой истории покупок подключите `purchaseDetails.canRepeatPayment` и операцию повтора с JWT покупателя. При переопределении оформления сохраните транзакцию подготовки и вызов провайдера после commit. Проектный обработчик успешной оплаты выполняется под блокировкой заказа. Для собственного провайдера рекуррентных списаний реализуйте остановку продления в его сервисе Billing. Проверьте получение роли при запоздалом подтверждении, одно продление при двух оплаченных попытках и сохранность корзины при ошибке оформления.
