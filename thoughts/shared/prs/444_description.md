## Summary

Покупатель открывает свои заказы и чаты из профиля и меню аккаунта. В карточке заказа видны обложки и стоимость товаров, количество, статус и данные оформления. Покупатель может открыть товар, скачать чек и продолжить переписку с исполнителем. Сообщения из заказа и из раздела «Чаты» попадают в один тред, который доступен продавцу в CRM.

Closes #442.

## Changes

- Добавлены варианты RBAC Widget и Subject, проекции Studio и 16 снимков записей Host, RBAC и Website Builder для списка и карточки заказа. Варианты используют реестры singlepage/startup, локализованные ссылки и существующий профильный макет.
- SDK Subject возвращает покупателю состав и этап исполнения его исторических заказов. Карточка получает пару chatId/threadId только после проверки прав заказа и переписки. Старые заказы открываются и без обсуждения.
- Раздел «Чаты» объединяет членство всех профилей текущего пользователя. Поиск учитывает отображаемое название на выбранном языке до постраничной выдачи. В открытом чате покупатель переключается между «Все чаты» и «Обсуждения чата», в том числе для чата с единственным обсуждением. Владелец чата может начать новое обсуждение из этого списка.
- Для метаданных приватных страниц Host разрешает явные ссылки на собственные локализованные поля Page. Связанные Metadata сохраняют прежний приоритет.
- Список и карточка используют вариант Ecommerce Product `customer-order-line`. Карточка показывает сохранённые данные о получении и оплате, почту для чека и доступные квитанции. Под ней сразу открывается переписка.
- Общие всплывающие уведомления Host и их проекция в Studio получили оформление по предоставленному образцу. Слева расположена цветная иконка, справа — кнопка закрытия. Уведомления с действием показывают его под текстом.

## Notes

Отдельный тест Studio на имена импортов компонентов обнаруживает четыре прежних импорта в проекциях CRM и Social.

Для повторной ручной проверки нужны пользователь с заказом и отдельная сессия исполнителя с доступом к соответствующей задаче CRM. Тестовые аккаунты и платёжные данные хранятся только локально.

## Downstream migration

Примените стандартный seed новых записей страниц и виджетов. Если проект переопределяет меню аккаунта или профиль, добавьте в его варианты локализованные ссылки на `/rbac/subjects/orders` и `/social/chats`. Для собственных представлений переиспользуйте вариант Product `customer-order-line` и общий адаптер Toast. Данные заказа читайте через SDK текущего Subject с `includeCustomerDetails` и передавайте в Social проверенные идентификаторы чата и треда. На клиентской установке откройте список и заказ из обоих меню, отправьте реплику в тот же тред из CRM и убедитесь, что с другого аккаунта заказ недоступен.
