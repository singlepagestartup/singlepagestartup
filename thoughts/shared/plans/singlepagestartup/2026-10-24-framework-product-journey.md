## Результат

Посетитель понимает, как подготовить бизнес-модель и материалы в AI Chat,
проверить и экспортировать документы, а затем передать их кодирующему агенту
для разработки лендинга или продукта на Code Framework. Сам Framework остаётся
бесплатным и доступным независимо от покупки токенов. Автоматическое создание
и размещение сайта через hosted AI Chat остаётся будущей возможностью.

Лендинг `/framework` содержит описание возможностей и модулей, подготовку
материалов, локальный запуск, статьи, цену и FAQ. Навигация соединяет его
с блогом, статьями, покупкой токенов и AI Chat. Блог показывает категории,
авторов, обложки, код и ссылки на конкретные файлы GitHub. Страница `/ecommerce`
объясняет Pro и пополнения и ведёт к аккаунтному checkout AI Chat.

## Последовательность и критерии

1. **Основания и содержание — исправлены, подтверждения документов ожидаются.** Проверить опубликованные изменения
   GitHub, исправить устаревшие владельческие документы и зависимости, сохранить
   неподтверждённые состояния. Уточнённый пользователем путь применить к обоим
   продуктам. Existing Living Focus, Onest, Phosphor и зарегистрированные
   изображения составляют визуальную основу. Глобальные изменения Strategy,
   Brand и Design не получают автоматического подтверждения.
2. **Product Storybook — реализован и технически проверен.** Создать независимые от Modules/SDK страницы:
   лендинг, обзор модулей, блог, категорию, статью, публичную покупку токенов.
   Сохранить редактируемые Markdown-источники. Переходы между продуктами должны
   выбирать нужную страницу и Layout, не выбрасывая посетителя из Storybook.
   Объяснение подготовки должно быть заметным и вести в работающий прототип.
3. **Проверка Product — пройдена, три замечания review закрыты.** Проверить desktop и 320 CSS px,
   все навигационные переходы, карточки, фильтры, FAQ, копирование, выбор валюты
   и пакета, состояния локального checkout. Проверить реальные screenshots,
   console и целевые типы/тесты. Независимый reviewer проверяет критерии; при
   замечаниях выполнить доработку. Не запускать тяжёлые сборки параллельно.
4. **Studio Modules / Host — реализован и проверен.** Перенести проверенный продуктовый
   состав в публичные варианты модулей и Host stories. Сохранить модельные,
   Widget и relation границы, единичные model loading и grid Widget loading.
   Product не импортирует эти реализации. Проверить свойства и состояния через
   публичные entrypoints и отдельного reviewer.
5. **Runtime — реализован, source review и локальная публикация проверены.** Перенести композицию через Website Builder
   presentation Widgets, доменные Widgets и точные relation instances. Контент
   менять через явный SDK data-management flow, не repository snapshots.
   Сохранить регистрацию, социальные профили/авторов, корзину, валюты, checkout,
   токены, CRM и закрытый контент; проверить client/server границы и доступ.
6. **Приёмка — публичный dev-путь проверен; production и авторизованный документ ожидают проверки.** Запустить `npm run api:dev` и
   `npm run host:dev`, проверить реальные маршруты и основные сценарии. Выполнить
   scoped type/test/review проверки и необходимую проверку production RSC с
   ограниченными ресурсами. Обновить артефакты #376 и оставить финальный Code
   Review пользователю. Pull request, push, merge и deploy не входят в эту работу.

## Неизменяемые условия

- Free: 3000 токенов один раз при регистрации.
- Pro: 5000 токенов в месяц за 29 USD или 1900 рублей.
- Пополнения: 100/300/500/1000/3000 рублей по 0,13 рубля за внутренний токен;
  расчёт списаний сохраняется.
- Расхождение между порогом из бизнес-условий и положительным admission gate
  в опубликованных исходниках фиксируется как несовпадение доказательств.
  Существование кода не меняет подтверждённые пользователем финансовые условия.
- Фото изображают концептуальные сцены, без заявлений о реальных клиентах,
  команде или достигнутых результатах. Оригиналы и square deliveries сохраняются.
- Изменения сохраняются небольшими локальными коммитами с downstream trailers.
  Нельзя считать проверки старого checkpoint доказательством новых страниц.

## Runtime checkpoint

Production-компоненты используют собственные SDK и точные сохранённые relations;
Studio imports в runtime не добавлены. Framework, 15 справочных страниц, Blog,
curated token catalogue и общая навигация опубликованы локально через явные
SDK-входы. Повтор и итоговый fresh prepare обоих входов не требуют изменений.
Первый cutover также прошёл rollback/reapply с сохранением additive records.

Desktop и 320 CSS px проверены в браузере: ссылки, карточки, FAQ, копирование,
Slider, Blog/author/TOC, currency и выбор пакета. Guest private Widget отсутствует
в DOM, прямой GET возвращает 403/private no-store. Финансовые и CRM операции
в этом проходе не отправлялись. Scoped runtime TypeScript и профильные тесты
проходят; независимый reviewer закрыл все source/CMS findings в своём scope.

Полная production-сборка не принята. После heap OOM и ограниченной Turbopack
попытки проверены полный Webpack build и явные последовательные compiler workers
(`53ca2a4098`). Server compiler завершается и освобождает память, но два полных
прохода с heap 2304/2048 MiB остановлены общим 3 GiB RSS watchdog. Source review
не подтверждает unsafe client-to-server import, но не заменяет успешную сборку.

Панель передачи документа проверена 16 runtime-component regressions. Disposable
runner прошёл независимый source review после исправления capture preflight;
данные и credentials не создавались. Обычный IAB с новым Host origin не изолирует
API cookie jar, поэтому для live auth-прохода принят отдельный private context.
Native CUA недоступен при блокировке macOS. Авторизованный browser-проход остаётся
непроверенным. Эти два ограничения сохраняются для Code Review.
