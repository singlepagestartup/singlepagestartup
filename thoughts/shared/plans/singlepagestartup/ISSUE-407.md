# План реализации #407. Заказы и корзина выбранного профиля

## Результат и границы

Каждый новый заказ, включая открытую корзину, принадлежит ровно одному `social.profile`. Аккаунт подтверждает право действовать от имени профиля. У аккаунта с профилями A и B один товар может лежать в обеих корзинах. Количество, сумма, покупки, чеки и действия с заказом относятся к выбранному профилю.

| Сценарий                    | Ожидаемое поведение                                                                                                                                                                                                                                                                                                                                              |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Гость                       | Первое добавление товара или прямая покупка создаёт личный профиль гостя один раз. Регистрация сохраняет его корзину. После входа в существующий аккаунт сервер автоматически объединяет открытую гостевую корзину с корзиной активного профиля. Разные товары сохраняются, а для одинакового товара остаётся количество из позиции, которую добавили последней. |
| Выбор профиля               | Автоматически создаётся один личный профиль. Если он единственный, все новые заказы сразу принадлежат ему. Другие уже доступные профили можно выбрать в нижней части существующего меню аккаунта. При одном профиле меню показывает только обычные действия. Создание дополнительных профилей из меню в эту задачу не входит.                                    |
| Покупка от имени ассистента | Заказ виден в профиле ассистента. Роль и пополнение получает аккаунт покупателя, ему же доставляется уведомление о покупке.                                                                                                                                                                                                                                      |
| Initial Free                | Бесплатная подписка выдаётся один раз на аккаунт. Заказ принадлежит его личному профилю. Повторный вход или переключение на другой доступный профиль не дают вторую подписку.                                                                                                                                                                                    |

В объём входят интерфейсы магазина и AI Chat, API, SDK, Telegram Stars, подписки, фоновые операции и объединение открытых корзин при входе. Старые проекты обновляются отдельно с удалением выполненных заказов. Перенос истории в новую модель в эту задачу не входит, в том числе у аккаунтов с одним профилем.

## Исходное состояние

Три пути записывают владельцем заказа аккаунт. API читает его заказы через ту же связь, а ключ React Query содержит ID аккаунта. Фоновый обработчик использует эту запись и для выдачи роли или пополнения. Сейчас профиль ассистента может быть связан и с человеком, и со служебным аккаунтом агента. Определять получателя покупки по первой связи профиля нельзя. ## Этап 4. Подключить витрину и проверить покупку целиком

В рабочем меню `me-account-ai-chat`, которое использует и витрина, вывести дополнительные профили под пунктом «Выйти». Хранить `socialModuleProfileId` в `sessionStorage` текущей вкладки отдельно для каждого `subjectId`. При входе восстановить доступный профиль этого аккаунта, иначе выбрать личный. При переключении, выходе или отзыве доступа обновить выбор и связанные запросы. Кнопки товара, корзина и «Покупки» получают ID от общего компонента, который ведёт этот выбор. На профильных страницах Host согласует именованный сегмент URL с выбранным доступным профилем. Переход по ссылке и переключение в меню должны приводить к одному и тому же профилю для экрана и запросов. Для Telegram Stars использовать известный профиль отправителя. ## Доработка после review: повтор заказа

Пользователь разрешил повтор заказа как способ заново выбрать оплату после ошибки. В истории добавить действие «Повторить заказ». После подтверждения сервер заменяет все открытые корзины `cart/new` выбранного профиля товарами и количествами исходного заказа. Профиль исходного заказа и выбранный профиль должны совпадать. Исходный заказ, счета и обработка платежей сохраняются. Для ожидающей оплаты подтверждение сообщает, что прежний счёт продолжает действовать.

Создавать новые ID заказов и строк, переносить магазин и проверенную доступную валюту. Цены рассчитываются текущим checkout. Перед заменой проверить доступ, товары, количества, магазин и валюту; всю замену выполнить одной транзакцией под общей блокировкой профиля. Ошибка сохраняет прежнюю корзину. Другие профили и заказы в оплате не изменяются. Повтор не запускает платёж автоматически: пользователь открывает восстановленную корзину и выбирает доступный метод оплаты.
