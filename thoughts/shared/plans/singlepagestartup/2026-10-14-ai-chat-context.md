# Управление контекстом AI Chat и Telegram

Утверждённый объём: общий механизм RBAC для AI Chat и Telegram, последние три обмена репликами и текущий запрос точно, отдельный точный рабочий документ, краткое состояние старой истории и scoped чтение оригиналов. Knowledge остаётся источником бизнес-фактов. Большой документ имеет приоритет над мягким бюджетом. Модель — GPT 6.1 Sol high. Бюджет реального опыта — до $5.

Гипотеза Lean Startup: снижение полной стоимости длинных тредов минимум на 50%, включая сжатие, без ошибок в критических фактах, документных подтверждениях и доступе. Первый выпуск использует существующие слои SPS, Thread metadata и сервисы; новые таблицы, UI и внешняя память не нужны.

## Реализация

- [x] Версионированные контракты RBAC состояния и метрик; Social атомарно обновляет один непрозрачный namespace metadata, сохраняя остальные.
- [x] Предложения документа и настройки модели используют атомарное обновление.
- [x] Context service через публичный Subject service и заменяемую фабрику; порядок истории по времени/ID до trigger, служебные исключения и `/new`.
- [x] Мягкий бюджет 12 000, Knowledge excerpts 3 000; последние три обмена и рабочий документ точно. Оценка js-tiktoken o200k_base с запасом 20%, фактический provider usage отдельно.
- [x] Инкрементальное сжатие при 8 000 токенов старой истории, до 16 000 входа за вызов, вывод до 2 048 и ориентир summary 1 000. Необработанная история сохраняется.
- [x] Проверка версии/hash, инвалидирование изменённой истории, fallback на исходный текст; сжатие не сохраняет Knowledge.
- [x] Native tools точного рабочего черновика, scoped чтения истории и оригиналов вложений с подачей media в следующий шаг модели.
- [x] Постоянные инструкции в начале prompt, стабильный session_id, purpose=context_summary в общем billing; режим full для возврата.
