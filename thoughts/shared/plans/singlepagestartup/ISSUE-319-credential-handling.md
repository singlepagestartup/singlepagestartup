# Учётные данные при деплое и запуске cron

Cron вызывает публичный POST без учётных данных. Внутренний ключ RBAC остаётся
в API. При выкладке дождаться завершения старых обработчиков cron, применить
миграции Broadcast и обновить API. Затем переустановить серверную запись
crontab. Проверить ответ 204 без заголовков, один запуск при конкурентных
запросах и сохранение интервала после очистки просроченных сообщений.

## Остальные два исправления

- **Файлы с учётными данными.** В `create_inventory.sh` создавать временный файл в том же доверенном каталоге с `umask 077` и правами `0600`. Переименовывать после успешной записи. Применить это и к декодированному SSH-ключу. На сервере для env-файлов API, Host, MCP, Telegram и LLM явно задать владельца и режим `0600`. Повторный деплой должен исправлять ранее созданные файлы `0644`. Права задаются отдельным файлам. Каталог загрузок API принадлежит UID 1000 и проверяется отдельно.
- **Журнал Traefik.** Добавить `--accesslog.fields.queryparameters.defaultmode=drop` рядом с действующим правилом для заголовков. Оставить путь без query, статус и длительность запроса. На образе `traefik:v3.7` в предыдущей проверке эта настройка убрала оба тестовых OAuth-параметра. Это правило действует на новые записи. Доступ к старым копиям журналов и срок их хранения проверяются отдельно.

Проверить права при чистой установке с `umask 022` и при обновлении уже
существующего файла. Непривилегированный локальный пользователь должен
получить отказ при чтении. Проверить запуск сервисов и загрузку, чтение и
удаление файла через API под UID 1000. Для журнала отправить тестовый
успешный и ошибочный запросы с разными контрольными значениями в query,
Authorization и Cookie, затем проверить путь и статус в JSON и отсутствие
контрольных значений. Для первого соединения с нового CI-раннера нужен
заранее проверенный SSH-ключ сервера в `known_hosts`.
