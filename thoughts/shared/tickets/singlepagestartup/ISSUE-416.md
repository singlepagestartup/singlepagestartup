# Типизированный доступ к сервисам нижележащих модулей через this.modules

## Metadata

- Тип — рефакторинг
- Приоритет — средний
- Размер — large
- Статус — Research in Review
- GitHub — https://github.com/singlepagestartup/singlepagestartup/issues/416

## Задача

Серверные сервисы SPS получают зависимости несколькими способами. Например, Agent вручную описывает методы Order через IReadService и Pick. Дочерний проект может расширить Order в service/startup, но TypeScript скрывает новый метод от Agent. Требуется единый способ получать сервисы нижележащих модулей во всей серверной части SPS.

## Ожидаемое поведение

- Из Agent доступен каждый нижележащий модуль, его модели и связи. Иерархия действует и для промежуточных модулей. Проверки направления импортов охватывают типы и реэкспорты. Внутри модуля сохраняется порядок владения моделями и связями.
- Публичный метод, добавленный в Order/service/startup, вызывается как `this.modules.ecommerce.order.<метод>()`. TypeScript выводит его параметры и результат из реализации Order. Для нового метода достаточно изменить сервис модели.
- Контроллер Order и вызывающий сервис получают один экземпляр Order в одной сборке. Обращение к сервису не запускает HTTP-приложение. Тестовая сборка и дочерний проект могут подменить реализацию.
- Генератор поддерживает тот же порядок для новых моделей, связей и модулей. Пользовательские действия по-прежнему проверяются через Permission и RBAC Subject.
- Перед проектированием описать текущее устройство bootstrap, границы контейнеров, ручные биндинги, повторное создание экземпляров, генераторы и имеющиеся проверки. Согласовать поэтапный перенос и критерии проверки в Core 20.
