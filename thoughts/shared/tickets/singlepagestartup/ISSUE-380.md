# SEO для сборки страниц Host, блога и каталога

## Metadata

## Problem to Solve

Общие механизмы сборки страниц должны выдавать корректные метаданные и адреса для индексации статических страниц, статей и товаров. Яндекс Вебмастер m2commerce.ru сообщает о 129 страницах с одинаковыми title и description (91%). В примерах title — «М2коммерц», включая /ru, /ru/ivanovmaksim-estate и /ru/self-storage-skladno-rent. В поиске присутствуют URL товаров с рекламными параметрами. Сводка и экспорт отчёта временно ограничены на стороне Яндекса.

## Key Details

- Проверить текущие SSR-метаданные, canonical и языковые альтернативы, robots.txt, sitemap, HTTP-статусы отсутствующих страниц и структурированные данные.
- Сохранить редактируемые SEO-значения Host Metadata и согласовать их с конкретным контентом динамических страниц.
- Исправить подтверждённые проблемы общего механизма и добавить проверки поведения.
- Сопоставить исправления с официальной документацией поисковых систем и Next.js.

## Implementation Notes

- Ветка: codex/studio-linear-workflow; переключение и новая ветка запрещены пользователем.
- В рабочем дереве есть изменения Studio и shared workflow, существовавшие до SEO-задачи; они не входят в её scope.
- Пользователь поручил пройти Core 00 → исследование → план → внедрение и проверку. В репозитории Core 30 является внедрением, следующий статус — Code Review; Core 40 отсутствует.
- m2commerce.ru — production-пример downstream-проекта; этот checkout принадлежит singlepagestartup/singlepagestartup. Локальные исправления сами по себе не обновляют production.
- Не изменять repository data snapshots. Развёртывание и изменение содержимого production требуют отдельного конкретного действия после проверки общего кода.

## Уточнения для проверки плана

- Текущий результат — вторая редакция плана для повторной проверки. Продолжение кода, коммит и PR ожидают согласования.
- Маски используют квадратные скобки и имена module/models/field, учитывают локаль и реальные связи. Хранение SEO — существующая модель Metadata и связь с Page.
- JSON metadata у контентных моделей рассматривается как расширение для keywords и других дополнительных данных. Пользователь запросил оценку выгод и проблем; добавление поля во все модели не утверждено.
- У всех моделей и связей требуется hidden. Скрытая основная сущность страницы возвращает 404 и исключается из индексации; отдельный draft не нужен.
- Для изображений нужны маски и связь Metadata → File с запасной обложкой. План должен объяснять author, viewport и структурированные данные.
