# Issue #418: Связать CRM-воронки, работу персонального ассистента и исполнение заказов

**URL**: https://github.com/singlepagestartup/singlepagestartup/issues/418

**Priority**: medium
**Size**: large
**Type**: feature

## Problem to Solve

Менеджер должен уметь описать работу обычным текстом и поручить её человеку или ИИ. Сегодня консультация, ответ AI-чата, корзина, оплата и выдача покупки имеют собственные пути исполнения. Для клиента нужен один разговор по поручению, для руководителя — история этапов, результатов и расходов.

## Key Details

- Воронка задаёт цель, условия начала и завершения этапов, инструкции, доступные операции, ответственного, плательщика, напоминания и исход при молчании. Новое обращение выбирает воронку и создаёт новую задачу. Повтор доставки одного события безопасен.
- «Задать вопрос» ведёт в новый тред задачи по конкретному товару и предложению. Заказ создаёт или использует черновик корзины, связывает задачу с покупателем, создаёт чат с дефолтным тредом. Готовый товар можно оплатить сразу, услугу по тарифу с приёмкой — после выбора результата. Переписка доступна после удаления из корзины.
- Для клиента сохраняется персональный субъект-ассистент с собственным профилем и балансом. Экспертный профиль хранит общие актуальные знания товара. Клиентский профиль хранит личные Knowledge Sources, в том числе по бренду. Для каждой задачи сервер выбирает источники, проверяет права чтения и записи и ограничивает инструменты. Исполнителем может стать менеджер.
- Расход владельца внешнего API-ключа, внутренние переводы токенов и покупка у магазина учитываются раздельно. Воронка задаёт основание оплаты, предложение — тариф. Личный ассистент может делегировать вызов отдельному Subject магазина для OpenRouter или OpenAI. У него свой кошелёк и исходящая RBAC Identity для защищённого ключа. Нужны бюджет до вызова, единая квитанция перевода и восстановление после таймаута.
- Поддержать оплату выбранного заказа, продажу услуги по принятому превью и выдачу приватного исходника после подтверждения платежа. Физические заказы используют тот же механизм для сборки, доставки и вручения.

## Implementation Notes

Сохранить направления зависимостей модулей, Subject API и проверки владения ресурсом. CRM хранит ход работы, Social — разговор, Knowledge — источники, Ecommerce — предложения и заказы, Billing — факты платежа. Распределение новых моделей и контрактов уточняется на ревью исследования.

## Критерии приёмки

1. Повторный клиент и новый клиент получают актуальную характеристику того же смартфона после обновления эксперта. Личная память одного клиента недоступна другому. Новая задача по тому же товару сохраняет персонального исполнителя и историю отдельных обращений.
2. Клиент с нулевым балансом спрашивает о пополнении на 300 ₽ за счёт собственника. В платной консультации применяются условия оплаты пользователем. Каждое движение связано с задачей и однократно отражается в кошельках.
3. Для физического товара и цифровой услуги руководитель меняет порядок работы через инструкции. Подтверждение оплаты, выдача файла, получение трек-номера и вручение имеют проверяемые основания. Повтор события после сбоя сохраняет одно исполнение.
4. По истории задачи видны версия инструкции, основание перехода, исполнитель, попытки, расход и исход, включая таймаут без результата, передачу человеку и подтверждённое исполнение.
