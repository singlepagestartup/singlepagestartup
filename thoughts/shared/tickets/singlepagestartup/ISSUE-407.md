# Привязать заказы к social.profile и разделить корзины профилей одного аккаунта

## Problem to Solve

Сейчас заказ связан с аккаунтом (`rbac.subject`) через `subjects-to-ecommerce-module-orders`. У аккаунта может быть несколько социальных профилей (`social.profile`). По связи с аккаунтом нельзя определить, какой профиль добавил товар в корзину или оформил покупку. Корзина и история заказов получаются общими.

Каждый новый заказ должен принадлежать одному конкретному профилю. Аккаунт по-прежнему определяет, кто выполняет операцию и к каким профилям у него есть доступ. Выбранный профиль определяет, с чьей корзиной и заказами он работает.

## Key Details

- **Выбор профиля.** Личный профиль создаётся автоматически один раз. Внизу существующего меню аккаунта после «Выйти» показываются другие уже доступные профили. Если профиль один, нижний блок скрыт. Нажатие на имя переключает профиль. Создание дополнительных профилей из меню в эту задачу не входит.
- **Гостевая корзина.** После входа сервер автоматически объединяет открытые корзины. Разные товары сохраняются. Если товар есть в обеих корзинах, остаётся последняя добавленная позиция с её количеством.

- **Проверка на двух профилях.** У одного аккаунта есть профили A и B. Оба могут добавить один и тот же товар в свои корзины. Изменение количества, удаление товара или оформление покупки в A не меняет корзину B. После переключения профиля список, количество, сумма и история соответствуют выбранному профилю, в том числе при возврате из кэша.
- **Доступ к отдельному заказу.** В контексте B нельзя прочитать, изменить, оплатить или отменить заказ A по его ID. Сервер проверяет доступ аккаунта к выбранному профилю и связь заказа с этим профилем.
- **После оформления.** Оплата, обработка заказа, подписки и уведомления должны находить исходный заказ по его профилю. При исследовании отделить владельца заказа от получателя роли, баланса или уведомления: перенос заказа сам по себе не меняет владельца этих сущностей.

## Implementation Notes

После ошибки оплаты пользователь может повторить заказ из истории: товары и количества заменяют текущую открытую корзину того же профиля. Исходный заказ и платёж сохраняются; новый checkout предлагает доступные способы оплаты. Перед заменой интерфейс запрашивает подтверждение и сообщает об ожидающей оплате исходного заказа, если она ещё не завершена.

Перенести оба покупательских сценария: добавление в корзину и прямую покупку товара. Отдельно учесть заказ начальной бесплатной подписки (Initial Free), который система создаёт при аутентификации. Учесть потребителей прежней связи в API, SDK, интерфейсе и фоновых задачах. Сохранить границы модулей: RBAC проверяет права, Social может связывать профиль с заказом, Ecommerce не импортирует RBAC или Social.

Кнопки корзины и покупки используют заранее выбранный профиль. Для веб-клиента выбор сохраняется в сессии вкладки отдельно для каждого аккаунта. Сервер проверяет права на профиль для каждого запроса.

Владельцы прежних проектов отдельно удалят выполненные заказы при обновлении своих установок. Задача меняет владение новыми заказами. Перенос прежней истории в профильные корзины не требуется.
