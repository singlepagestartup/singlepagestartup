### Incident 1 — Доступ из песочницы к сетевым сервисам

- **Phase**: Create / Implement
- **Occurrences**: 4
- **Symptom**: при загрузке конфигурации GitHub CLI сообщил `error connecting to api.github.com`.
- **Root Cause**: сетевой доступ из песочницы ограничен.
- **Fix**: та же команда с сетевым доступом подтвердила целевой репозиторий.
- **Preventive Action**: повторять штатный блок Bash с сетевым доступом, сохраняя конфигурацию репозитория.
- **References**: `.claude/helpers/load_config.sh`.

### Incident 2 — Настроенные модели исследовательских ролей недоступны

- **Phase**: Research
- **Occurrences**: 3
- **Symptom**: задачи ролей по поиску кода, анализу и поиску образцов завершились до чтения файлов.
- **Root Cause**: текущая сессия не поддерживает настроенные для этих ролей модели `gpt-5.4` и `gpt-5.4-mini`.
- **Fix**: три агента с доступной моделью прочитали канонические описания ролей и независимо проверили свои части кода.
- **Preventive Action**: при таком отказе перенести ту же узкую задачу и описание роли на доступную модель.
- **References**: `.codex/agents/codebase-analyzer.toml`, `.codex/agents/codebase-locator.toml`, `.codex/agents/codebase-pattern-finder.toml`.

### Incident 3 — Старые исследования описывают прежние обработчики

- **Phase**: Research
- **Occurrences**: 1
- **Symptom**: материалы #234 и #352 указывали на запись владельца в контроллерах и прежнее состояние проверок отдельного заказа.
- **Root Cause**: материалы относятся к более ранним ревизиям, часть операций перенесена в сервисы.
- **Fix**: ссылки в исследовании #407 ведут на текущие сервисы создания и проверки доступа в ревизии `ec863071e53b551f7430bb2fdc88fbfa640e11cf`.
- **Preventive Action**: сверять исторические ссылки с действующим контроллером и вызываемым им сервисом.
- **References**: [#234](../../research/singlepagestartup/ISSUE-234.md), [#352](../../research/singlepagestartup/ISSUE-352.md), [#407](../../research/singlepagestartup/ISSUE-407.md).

### Incident 4 — Исследование оставляет выбор за владельцем продукта

- **Phase**: Plan
- **Occurrences**: 1
- **Symptom**: выбор гостевого профиля, разбор неоднозначных старых заказов и получатель покупки ассистента влияют на критерии приёмки.
- **Root Cause**: стандартная схема хранит владельца прежнего заказа только на уровне аккаунта. У ассистента возможны связи с несколькими аккаунтами.
- **Fix**: пользователь подтвердил три предложенных правила и порядок четырёх этапов. При проверке плана правила гостевой корзины и старых заказов уточнены. Текущие условия приведены в разделе Plan.
- **Preventive Action**: перед записью плана закрепить, какой профиль владеет заказом и как определяется получатель оплаты в каждом сценарии.
- **References**: исследование #407, раздел Open Questions, шаги 2.5 и 4d–4e регламента core/20-plan.

### Incident 5 — Статический маршрут попал под middleware параметра профиля

- **Phase**: Implement
- **Occurrences**: 1
- **Symptom**: POST profiles/ensure пытался прочитать ensure как UUID.
- **Root Cause**: параметрический middleware зарегистрирован раньше статического маршрута.
- **Fix**: статический маршрут зарегистрирован первым. Сценарий реального API прошёл.

### Incident 6 — Чтение гостевой корзины пыталось создавать профиль

- **Phase**: Implement
- **Occurrences**: 1
- **Root Cause**: общий resolver мог записывать данные внутри read-only snapshot.
- **Fix**: чтения без профиля возвращают пустые данные. Создание профиля выполняется перед первой записью заказа.

### Incident 7 — Ошибки исходных общих проверок

- **Phase**: Implement
- **Occurrences**: 1
- **Symptom**: три проверки Admin snapshots, общий TypeScript и проверка дублирования инструкций не проходят.
- **Root Cause**: в исходных snapshot отсутствуют связи Admin для GET ecommerce/orders, social/messages/count и notification/templates/count. TypeScript сообщает 60 ошибок в неизменённых файлах. Проверка инструкций находит 11 повторяющихся предложений.
- **Fix**: ошибки реализации исправлены. Исходные ограничения перечислены в журнале и описании PR.

### Incident 8 — Общая блокировка перехода гостевой корзины

- **Phase**: Implement
- **Occurrences**: 1
- **Root Cause**: прежние checkout и регистрация не участвовали в блокировке новой операции объединения корзин.
- **Fix**: checkout атомарно закрепляет заказы до обращения к провайдеру. Регистрация пишет identity и связи через локальные сервисы в транзакции под блокировкой исходного Subject. Проверки пересечений запросов прошли.

### Incident 9 — Dump больше не доступен через HTTP

- **Phase**: Implement
- **Occurrences**: 1
- **Symptom**: SDK Permission не содержит dump, а HTTP /dump обрабатывается как ID.
- **Fix**: Permissions созданы владеющим SDK, затем экспортированы штатным dump владеющего service в CLI. В репозиторий включены только предназначенные новые разрешения.
- **Preventive Action**: использовать стандартный процесс dump в CLI.

## Reusable Learnings

При проверке владельца заказа различать два вопроса: имеет ли аккаунт доступ к профилю и какому профилю принадлежит заказ.
