- Notes: Этапы подтверждены. Geoapify — первый заменяемый серверный адаптер. Для приёмочного примера адаптер возвращает 24 км. В план включены проверка остатка при выставлении счёта, повторные уведомления об оплате и независимая оплата по валютам.

- Billing: поля amount у Invoice и Payment Intent сейчас целочисленные. В этап оплаты включить сохранение дробных денежных сумм, совместимость действующих счетов и проверку округления у платёжных адаптеров. См. `libs/modules/billing/models/invoice/backend/repository/database/src/lib/fields/singlepage.ts:12` и `libs/modules/billing/models/payment-intent/backend/repository/database/src/lib/fields/singlepage.ts:8`.

- Уточнение модели для согласования: способы получения и услуги следуют из связей SKU. Версионированная формула тарифа запрашивает только используемые входы. Для слияния корзин описана замена всего последнего выбора товара, включая разделённые строки. Для подписки различаются первая и последующие поставки. В исследовании приведены условия Geoapify и Яндекса, самостоятельный OSRM и пример Tasty Coffee.

- Проверен один запрос Geoapify по публичным координатам: 5 706 м, HTTP 200. В исследование добавлены формулы Product, ставки по ключам атрибутов Store и пример трёх заказов с двумя валютными счетами. Структура заказов вынесена на согласование до подготовки плана.

- Уточнение при планировании: лимит привязан к SKU магазина через числовой атрибут. В критерии добавлены суммарный лимит по строкам, конкурентная покупка последней единицы и серверный выбор валют для комплекта услуг. Открытая корзина не резервирует товар. Резерв создаётся при подготовке счёта, списывается однократно при оплате и освобождается при окончательной отмене.

### Incident 1 — запуск исследовательских агентов

- **Phase**: Research
- **Occurrences**: 2
- **Symptom**: Два экземпляра codebase-analyzer завершились до чтения кода.
- **Root Cause**: Закреплённая за ролью модель gpt-5.4 недоступна в текущем режиме входа Codex.
- **Fix**: Три агента с доступной моделью параллельно проверили каталог, корзину и оплату по исходным файлам.
- **Preventive Action**: При таком сообщении повторить узкое задание с доступной моделью.
- **References**: `.codex/agents/codebase-analyzer.toml`.

### Incident 2 — загрузка ESM в Jest

- **Phase**: Research
- **Occurrences**: 1
- **Symptom**: Обычный запуск Jest завершился на загрузке path-to-regexp до выполнения части тестов.
- **Root Cause**: В этом checkout Node 24.11.0 запускал Jest без поддержки VM Modules для ESM-зависимости.
- **Fix**: С флагом `--experimental-vm-modules` прошли все десять выбранных наборов.
- **Preventive Action**: При такой ошибке использовать флаг Node из штатного сценарного скрипта. Для интеграционных тестов этой сессии потребовался доступ к локальной PostgreSQL.
- **References**: `tools/testing/test-scenario-issue.sh:234`.

### Incident 3 — источник дорожного расстояния

- **Phase**: Plan
- **Occurrences**: 1
- **Symptom**: Приёмочный пример задаёт 24 км, но не определяет, как получить расстояние для адреса покупателя.
- **Root Cause**: В исследованных пакетах Ecommerce и API нет источника маршрутов доставки.
- **Fix**: Для реального маршрута план использует серверный адаптер Geoapify с возможностью замены. Контрольные 24 км воспроизводятся с тестовым адаптером.
- **Preventive Action**: В плане отдельно описать расчёт для реального адреса и тестовые данные для 24 км.
- **References**: `thoughts/shared/plans/singlepagestartup/2026-11-17-store-offers-and-cart-services.md:50`.

### Incident 4 — Восстановление проверочной базы

- **Occurrences**: 1
- **Stage**: Проверка миграций
- **Symptom**: Старая схема требовала расширения vector, а восстановление одной схемы оставило таблицу состояния Consistency без начальной записи.
- **Root Cause**: Расширение устанавливает администратор PostgreSQL. Начальная запись создаётся миграцией и входит в данные таблицы.
- **Fix**: Установили расширение в отдельной базе, восстановили схему и журнал, создали новый epoch по правилу миграции. Повторный api:db:migrate и consistency-check завершились успешно.
- **Reusable Pattern**: При переносе только схемы восстановить необходимое служебное состояние.

### Incident 5 — Соединение таблиц при резервировании

- **Occurrences**: 1
- **Stage**: Резерв и оплата
- **Symptom**: Тест последней единицы выявил ошибку SQL в чтении атрибута остатка.
- **Root Cause**: В условии использовалось поле связи на таблице самого ключа.
- **Fix**: Исправили условие. Проверки гонки, повторной оплаты, отката и позднего уведомления прошли на PostgreSQL.
- **Reusable Pattern**: Проверять складскую транзакцию на мигрированной схеме с двумя покупателями.

### Incident 6 — Запуск API с Bun

- **Occurrences**: 1
- **Stage**: Сквозная проверка
- **Symptom**: Bun 1.3.6 завершал запуск API при загрузке undici 8.12.4.
- **Root Cause**: В поставке Bun отсутствовал worker_threads.markAsUncloneable, который вызывает undici.
- **Fix**: Для проверок установили Bun 1.4.4 во временный каталог. Локальный сервер запустился и рассчитал семь валютных цен штатного каталога.
- **Reusable Pattern**: Проверить запуск штатного API до проведения HTTP-сценариев.

### Incident 7 — Старые связи Admin в базовом dump

- **Occurrences**: 1
- **Stage**: Проверка прав и общего набора RBAC.
- **Symptom**: Тесты штатных данных не нашли Admin для списка заказов и двух счётчиков админки.
- **Root Cause**: Коммит `332c21e212` удалил связи, заданные в `40d8282abe` и `cb3d61ac94`. Ранее утверждённые тесты остались в проекте.
- **Fix**: Восстановлены исходные записи для списка заказов и его счётчика, а также двух счётчиков админки. Общий модульный прогон прошёл.
- **Reusable Pattern**: Проверять пары collection/count и сверять пропавшие связи с последним целевым коммитом перед массовым dump.

### Incident 8 — Очередь Consistency на проверочной базе

- **Occurrences**: 1
- **Stage**: Общий интеграционный прогон.
- **Symptom**: Тест доставки событий не успел обработать накопленную очередь после массовой загрузки фикстур.
- **Root Cause**: В проверочной базе накопились 15 376 ожидающих событий от предыдущих прогонов. Лимит итераций теста рассчитан на короткую очередь.
- **Fix**: Штатный диспетчер обработал очередь. Затем прошли все 16 интеграционных заданий.
- **Reusable Pattern**: При повторном использовании отдельной базы проверить состояние диспетчера после загрузки данных.

## Reusable Learnings

- При проверке суммы после оплаты проверять отдельно расширенное чтение заказа, список покупок Subject и сохранённый Invoice. Они используют разные источники цены.
