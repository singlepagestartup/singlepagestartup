## Что проверено

Admin v2 монтирует содержимое после клиентской проверки сессии и роли. Аутентифицированные чтения и формы используют клиентские SDK; backend RBAC сохранён. В локальном аутентифицированном браузере обе админки показывают одну и ту же Page→Metadata→File, приоритет и фильтрованный счётчик. На production проверены SDK-операции и публичный интерфейс. Новая Page получает язык из настроек; в браузере — ru. Проверены редактирование Metadata, переход к File, alt и draft preview.

В исходной БД заполнены 102 Page, в production — 104. У каждой выбрана отдельная Metadata и привязан отдельный File. Для семи разделов созданы обложки Living Focus; WebP весят 32–54 КБ. Оригиналы landscape и отдельно расширенные квадратные изображения сохранены в Workspace. В production все 104 URL изображений отвечают 200, SHA-256 совпадает с исходными байтами; MIME, размеры и alt проверены. Прежние Metadata и связи сохранены. Новый prepare/apply не создал Metadata, Page→Metadata, Metadata→File или новых File ID.

Статические тексты редактируются в Metadata, динамические Article/Product/Category/Author используют квадратные маски. Fallback сохранён. Keywords и автор берутся из заполненных данных. Приватные страницы сохраняют noindex; их SEO читает только конфигурацию Page/Metadata и обложки, без личных сущностей.

Публичный маршрут остаётся SSG/ISR с TTL 3600 секунд. На production: HIT → изменение связанной Metadata → новый title → HIT. Обновление title заняло около 1 с в проверенном прогоне. Hidden Page/Article/Product возвращают 404 после прогретого ответа; восстановление — 200. Обязательная Category–Article связь тоже даёт 404 при hidden; отдельная статья остаётся 200. Все остальные поля и ключи сохранены, собственный тестовый Page удалён. Публичный cookie не меняет HTML/HIT. Несуществующие страницы, slug и файлы возвращают 404; анонимный includeHidden — 403. `/` перенаправляет 308 на `/ru`, рекламные параметры отсутствуют в canonical.

Production sitemap: **136 URL**, все 200, canonical/lang/description/OG и ровно один H1; 0 noindex и ошибок JSON-LD. Форма `/blog/new`, демонстрационные Store и служебные маршруты исключены. Четыре ранее скрытые пустые тестовые статьи сохранили hidden после startup. В исходной БД восстановлены title/subtitle/description Analytic из точной прежней резервной копии с совпадающими ID/slug; остальные поля сохранены. Полный локальный обход после восстановления: 124 URL, те же проверки пройдены.

## Что оптимизировать следующим

1. **Сначала загрузка и сдвиги вёрстки.** Next build показывает 1,71 МБ клиентского JS при первом открытии (First Load JS); Lighthouse оценивает неиспользуемый JS примерно в 1,1 МиБ. Framework передаёт 7 440 КиБ ресурсов, список статей — 8 250 КиБ. LCP на внутренних страницах 12–24 с, CLS до 0,544. Следующий технический этап — анализ bundle, загрузка admin/редких вариантов по необходимости и резервирование геометрии контента до загрузки изображений/виджетов. Точки разбора: `apps/host/src/components/admin/ClientComponent.tsx` заранее импортирует Dashboard; модельные `singlepage/variants.ts` объединяют публичные и административные варианты. Их точный вклад нужно измерить, сохранив SSR текста и SDK/Provider-контракты. На внутренних страницах также отсутствует семантический элемент `<main>`, у статей есть пропуски уровней заголовков.
2. **Уже можно заполнить редакторами:** восемь адресов каталога используют общий английский description. Это обе локали категории `important-tomato-bonobo` и товаров `free-subscription`, `startup`, `website`. Нужны фактические описания в полях сущностей или `metadata.seo.description`; маски уже подключены. Остальные шесть групп повторов description — пары en/ru тестовых статей/категорий. Повторов title внутри одной локали нет; 24 группы между en/ru требуют проверки переводов. Hreflang следует добавлять для реально соответствующих переводов. [Языковые версии Google](https://developers.google.com/search/docs/specialty/international/localized-versions). Meta keywords Google не использует для индексации и ранжирования, поэтому это не первый приоритет. [Поддерживаемые метатеги](https://developers.google.com/search/docs/crawling-indexing/special-tags).
3. **Доработать общий FileInput.** Браузерная проверка сохранения существующего File повторно загрузила те же байты и изменила URL; размеры и alt сохранились. `libs/shared/ui/shadcn/src/lib/file-input/index.tsx` превращает исходный URL в File и вызывает onChange при инициализации. Следует оставить существующий URL значением предпросмотра, а бинарный PATCH отправлять только после выбора замены. Проверка исправления: изменение одного alt сохраняет file/size/width/height и не вызывает upload.
4. **Стабилизировать seed Metadata.** До выпуска было 45 Metadata, после startup до нашей публикации — 47. У Metadata seed нет filters сопоставления (`libs/modules/host/models/metadata/backend/app/api/src/lib/configuration.ts`). Нужны стабильный ключ и отдельное согласование дублей с сохранением редакторских значений и файлов. Порядок наших связей стабилизирует текущий выбор, но не устраняет причину роста.
5. **Позже расширить контентные сценарии.** Для настоящего Store нужен собственный Metadata content context и публичная композиция; нынешний demo остаётся noindex. Для Product offers нужны подтверждённые цена, валюта и доступность; авторы, даты, рейтинги и отзывы добавляются при наличии источника. В двух статьях Lighthouse фиксирует внешние CORS-ошибки Webvisor, Best Practices — 73; в остальных — 77. Режим Метрики/Webvisor стоит проверить отдельно. В ручной браузерной проверке Social ошибок приложения нет.
