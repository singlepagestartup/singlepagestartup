## Результат проверки SEO, ISR и данных

Релиз: [0.0.330](https://github.com/singlepagestartup/singlepagestartup/releases/tag/0.0.330). Код: [`8324e42e97`](https://github.com/singlepagestartup/singlepagestartup/commit/8324e42e97a6630680833e16158d99eabf5b94bd). Проверка: 30.10.2026, Europe/Moscow. Ветка `codex/studio-linear-workflow`.

Публичные страницы используют ISR с часовым TTL и инвалидизацией зависимостей. Язык берётся из маршрута `[language]`; админка имеет отдельный динамический маршрут. Маршрут передаёт путь и язык в Page document, а загрузкой и SEO управляют модели Page и Metadata. Проверка существования завершается до начала потокового ответа. Сессия и персональные операции остаются в клиентских domain readers.

Релиз завершён успешно; Portainer подтвердил работающие Host и API именно 0.0.330. На сервере проверены HIT, изменение title и повторный HIT, hidden → 404 → восстановление 200 для Page, Article, Product и обязательной Category–Article связи. Независимая статья остаётся доступной при скрытии связи. Cookie не меняет публичный HTML/HIT. На localhost:3000/ru и странице модуля в браузере нет ошибок приложения или прежнего сообщения root layout.

### Данные и поведение страниц

- Сохранены исходные английские Page; созданы 52 русских шаблона со связями к существующим Widget, Layout и Metadata. Повторное чтение подтвердило 52 соответствия. Копия маршрута не заменяет перевод содержимого; автоматический hreflang не добавляется.
- Шаблоны статей и товаров связаны с Metadata. Title/description берутся по квадратным маскам из локализованных полей; обложки — по явным связям с File Storage. Предпросмотр проверен в ru/en. Keywords берутся из `metadata.seo.keywords`, если они заполнены.
- На страницах модулей и авторов добавлен существующий Page Header через стандартные связи. У одной статьи убран точный повтор заголовка из единственного вложенного виджета, основной H1 и текст сохранены.
- Четыре полностью пустые тестовые статьи переведены в hidden: `pr260-cookie-1789835093`, `x-1789775862`, `pr260-conflict-1789834956`, `article-4`. Изменение обратимо; записи сохранены.
- Демонстрационный шаблон статей и две страницы единственного тестового магазина `single-page-shop` имеют noindex. Магазин доступен; отдельные страницы товаров индексируемы. Для публикации настоящего Store потребуется его собственная SEO-композиция и смена политики Page.
- Через Metadata→File настроены общая обложка Code Framework и отдельная фотография главной. Использованы существующие опубликованные PNG 1254×1254; размеры проверены по байтам файлов. Свои маски статей и товаров имеют приоритет.
- Текущая Metadata главной имеет явный приоритет orderIndex=-1 в обеих локалях. Существующие записи сохранены.

Sitemap до выпуска содержал 46 729 адресов, включая 45 159 адресов AI Chat. После изменений: 138 адресов; все 200, canonical соответствует URL, lang соответствует локали, описание и OG-обложка заполнены, ровно один H1; 0 noindex, служебных URL и ошибок JSON-LD. Неизвестные и hidden-адреса возвращают 404. При локальной контрольной остановке API прогретая страница сохранила 200 HIT, холодная вернула 500 no-store, sitemap — 503 no-store с Retry-After: 60. HTML содержит canonical, lang, robots и серверный текст статьи/товара. JSON-LD использует фактические данные, без вымышленных авторов, дат, offers и рейтингов.

### Исправления общего кода

Обнаружен и устранён дефект PATCH: общий Repository применял insert schema к частичному обновлению и подставлял пустые JSON по умолчанию. Изменение только variant могло стирать локализованные поля. Теперь update использует partial schema; неизменяемые поля и внешние ключи сохраняются, явно переданный `{}` по-прежнему очищает нужное поле. Добавлены регрессионные тесты.

При серверной проверке дефект затронул `framework-blog` и `framework-landing`. Полного JSON-backup этих записей до первого сценария не было. Их локализованные поля восстановлены через SDK из версионированных записей с совпадающими slug/adminTitle. Название статьи также совпадает с HTML, сохранённым до проверки. Усиленный сценарий сохраняет полные записи до изменений и проверяет все поля после hidden и восстановления. Повторный production-сценарий 0.0.330 подтвердил сохранность всех полей Page, Article и Product; отдельный сценарий — сохранность внешних ключей и полей связи. Данные перед повторным сценарием восстановлены в finally, созданная тестовая Page удалена. Локальная транзакционная проверка этих же моделей завершилась откатом.

Seed Page теперь использует URL и язык вместе, как уникальный ключ БД. Snapshot без языка использует значение по умолчанию из схемы. Реальная проверка в транзакции исходной локальной БД сохранила 51 русскую Page и сопоставила 51 английскую; транзакция откатилась.

Также убраны циклический импорт Metadata SDK, обращения к API из global error и цикл перезагрузки ошибки. Отключён preload всех начертаний шрифтов. Публичные SDK reads имеют конечный кеш и теги; авторизованные reads и draft preview используют no-store.

### Рецензия и следующие улучшения

Ближайший этап: пункты 1–3 — bundle, геометрия/изображения и описания. Пункты 4–7 требуют отдельной модельной задачи или настройки продукта. Состояние индекса в пункте 8 проверяется после переобхода.

1. **Клиентский JavaScript — высокий приоритет.** Публичная сборка содержит около 1,72 МБ First Load JS. Это подтверждено Docker build опубликованного образа. Реестр `libs/modules/host/models/widget/frontend/component/src/lib/singlepage/variants.ts` импортирует административные и публичные компоненты вместе, а `apps/host/src/components/admin/ClientComponent.tsx` заранее импортирует Dashboard. Стоит разделить загрузку по вариантам и загружать админку по необходимости, сохранив серверный HTML публичного контента и текущие SDK/Provider-контракты. Точный вклад импортов нужно измерить анализатором bundle.
2. **Отрисовка и сдвиги вёрстки.** У статей CLS 0,338–0,406, у Social — 0,506. Lighthouse показывает сдвиг основного блока статьи и указывает на позднюю геометрию изображений в File-композиции. Проверить контейнеры изображения до загрузки данных и резервирование aspect ratio; одни атрибуты width/height в поздно появившемся img не резервируют место заранее. Для Framework LCP 22,48 с требует отдельного разбора hero и загрузки картинки. На публичных статьях/Framework также отсутствует main landmark, в статьях есть пропуски уровней заголовков. Это следующий этап перед активным продвижением, вместе с разбором bundle.
3. **Редакторские поля и обложки.** Все 138 URL имеют OG-изображение: настроены общий fallback и обложка главной. Можно подготовить отдельные социальные обложки и более подходящие пропорции для разделов. Переводы, описания и тематические keywords заполняются в данных, без генерации вымышленных фактов. Дубли title: 29 групп, все между en/ru, внутри одной локали повторов нет. Из 24 групп одинаковых description одна включает 16 URL с общим английским текстом сайта: about, blog, ecommerce, Framework, тестовую категорию и три товара в обеих локалях. Нужны собственные описания этих страниц и перевод материалов, которые сейчас одинаковы в ru/en. Данные следует заполнить через редакторы/SDK, затем проверить повторным обходом. Google не использует meta keywords для ранжирования; [официальное описание метатегов](https://developers.google.com/search/docs/crawling-indexing/special-tags).
4. **Идемпотентность seed Metadata — проблема общего слоя данных.** У Metadata нет seed-фильтра, а insert создаёт новый ID. В исходных данных главной было восемь одинаковых связанных Metadata; новый seed добавляет записи. Явный порядок стабилизирует текущий выбор. Для устранения причины нужен стабильный ключ seed и миграция существующих дублей с сохранением редакторских значений и связей с файлами. Простое сравнение по изменяемому title не будет надёжным ключом.
5. **Store — отдельная модельная доработка.** Store поддержан в URL/sitemap, но пока отсутствует среди корней Metadata content context. Его полноценная публичная страница должна получать название, H1, описание и обложку из Store через owning reader. Текущая демонстрация исключена из индекса политикой Page, поэтому общий H1 не добавляется в layout.
6. **Расширенные товарные данные.** Product JSON-LD описывает фактические название, текст и изображения. Для offers нужны согласованные цена, валюта и доступность из товарных атрибутов. Рейтинг и отзывы можно добавлять при наличии реальных данных. Базовый Product не гарантирует расширенный сниппет.
7. **Best Practices и аналитика.** После выпуска Best Practices 77 на главной/Framework/модуле и 73 на двух статьях. Отчёты связывают снижение на статьях с CORS-ошибками запросов `mc.yandex.ru/webvisor`; это внешний ответ Вебвизора, ошибок приложения в проверенном браузерном сценарии нет. Third-party cookies Метрики и Chrome Issues присутствуют и в исходных отчётах; source maps имеют нулевой вес. Режим аналитики и cookies нужно выбирать по требованиям продукта.
8. **Фактическая индексация.** Проверены HTTP, HTML, robots и весь sitemap. Lighthouse SEO не подтверждает присутствие страниц в индексе Google и не проверяет весь сайт. Для фактического статуса нужен переобход подтверждённой Search Console/Вебмастера; подключённой Search Console в задаче нет. Выкладка выполнена на тестовом `singlepagestartup.com`; `m2commerce.ru` служил исходным примером и не обновлялся этим релизом.

Проверки кода: 281 пройденный тест, один прежний skipped; TypeScript в production build; scoped ESLint — 36 файлов без ошибок/предупреждений; зависимости — 15 494 файла, 0 нарушений. Проверки оригинальной БД и API выполнялись через SDK/Repository с readback и восстановлением. Публичный кеш имеет асинхронное окно инвалидизации и конечный TTL; добавление серверного session reader потребует повторной проверки изоляции.
