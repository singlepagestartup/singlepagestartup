# Web Designer methods

Load this file when mapping the visitor journey, specifying page content and
states, or reviewing responsive and accessibility constraints.

## Visitor-to-business map

For each primary visitor situation record question, anxiety, needed information,
proof, objection, action, form data, success feedback, business receiver,
response expectation, and next operational step. Use this map to sequence page
sections and states; do not begin from a generic landing-page pattern.

## Design specification

Specify actual copy and static compositions for desktop and mobile. Include
focus, error, empty, pending, and success states where relevant. Review hierarchy
at narrow widths, keyboard/focus implications, contrast, text alternatives,
labels, consent, and whether color or motion carries essential meaning.

Evidence-based design, iterative prototypes, clear rationale, and accessible
interaction are retained. Production code and broad technology selection are
outside this pre-development role.
