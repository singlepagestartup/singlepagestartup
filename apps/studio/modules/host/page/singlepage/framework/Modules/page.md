## Один проект — несколько задач

Для школы можно соединить каталог курсов, оплату, личный кабинет ученика и обсуждения. Для записи на стрижку собак — страницу услуги, форму с вопросами и уведомление о заявке. Вы выбираете возможности под свой бизнес.

## Расскажите, что должен сделать ваш клиент

Например: «Хочу продавать мастер-классы. Клиент выбирает занятие, оплачивает его и находит материалы в своём кабинете». С этой задачи можно начать разговор с ИИ-помощником и определить, какие модули понадобятся.

## Как связаны профили, чаты, ветки и сообщения

Представьте школу с авторами и помощником. Профиль отвечает на вопрос «кто», чат — «где общаемся», ветка — «о чём», сообщение — «что сказано». Связи соединяют эти записи.

| Модель         | Пример и назначение                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Profile · кто  | Дарья или помощник школы. Имя и описание представляют человека или помощника; связи добавляют статьи, знания и навыки. |
| Chat · где     | Переписка по проекту. Чат объединяет сообщения и тематические ветки.                                                   |
| Thread · о чём | «Обратная связь о лендинге». Отдельная тема со своей историей внутри чата.                                             |
| Message · что  | Вопрос, ответ или сообщение с файлом. Связи указывают автора, ветку и вложения.                                        |

## Что ещё есть в Social

Всего в модуле девять моделей. Дополнительные модели помогают настроить данные профиля, инструкции помощника и представление.

| Модель        | Для чего нужна                                                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Skill         | Повторно используемые инструкции для ИИ. Навык связан с профилем; в AI Chat явная команда /skill-slug включает подключённый навык для запроса. Само выполнение организует сценарий AI Chat.          |
| Attribute     | Типизированное значение профиля: строка, число, дата или логический признак. Например, направление работы эксперта.                                                                                  |
| Attribute Key | Описание такого поля: название, тип, префикс и суффикс. Задаёт подпись и формат отображения значения.                                                                                                |
| Action        | Запись события с данными и сроком действия. В AI Chat может хранить подготовленное представление работы помощника — например, обращения к знаниям. Правила выполнения остаются в управляющем модуле. |
| Widget        | Блоки для показа профилей и авторов. Они соединяют данные Social с оформлением страницы; авторизация переписки остаётся в RBAC.                                                                      |

## У каждого клиента — свой кабинет

Клиент регистрируется на вашем сайте и возвращается под своим именем. В его кабинете можно собрать покупки, переписку и доступные ему материалы. Вы определяете, что увидит посетитель, покупатель и сотрудник.

Вы продаёте курсы. Программу должен увидеть любой посетитель, уроки — купивший курс ученик, а список заказов — ваша команда. Когда эти действия происходят на одном сайте, проекту нужно узнавать человека и проверять, что ему разрешено. За эту часть отвечает модуль личных аккаунтов.

## Передайте повторяющиеся действия фоновым задачам

Определите, что должно происходить по расписанию или событию: обработать сообщение, подготовить материал, запустить уведомление. Модуль хранит настройки таких задач и запускает предусмотренные действия.

Одну операцию можно выполнить вручную. Когда она нужна каждый день или после каждого события, проекту требуется правило запуска. Например, подготовка сводки утром или реакция помощника на новое сообщение должна происходить без отдельного ручного запуска каждый раз.

| Заголовок                              | Содержание                                                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| У повторения есть расписание           | Задайте, как часто выполнять предусмотренную операцию. Сама операция и её входные данные должны быть настроены в проекте.       |
| Задача может реагировать на событие    | Запускайте обработку после появления нужных данных. В существующих сценариях так организована реакция ИИ-профилей на сообщения. |
| Автоматизацию можно развивать отдельно | Добавляйте новые задания по мере появления повторяющейся работы. Задача использует возможности других модулей.                  |

## Ежедневная сводка для владельца школы

Предположим, вы хотите утром получать список новых заявок. Для этого в проекте настраивают получение заявок, подготовку сообщения и его доставку. Agent задаёт запуск этого сценария по расписанию.

Agent не выполняет произвольную бизнес-задачу только по её названию. Нужны настроенные действия и подключения. Если действие использует ИИ или внешние сервисы, их вызовы могут расходовать токены или иметь отдельную стоимость.

## Показывайте изменения, пока человек работает на сайте

Новое сообщение, заявка или смена состояния могут появляться в уже открытом интерфейсе. Человеку не нужно обновлять страницу вручную, чтобы увидеть, что изменилось.

Администратор открыл список заявок утром. Если новые записи становятся видны только после перезагрузки, он может работать с устаревшим списком. Проекту нужен способ сообщить открытому интерфейсу, что данные изменились.

| Заголовок                                   | Содержание                                                                                                                      |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Переписка продолжается на открытой странице | Событие о новом сообщении позволяет интерфейсу обновить разговор. Сам текст и участники хранятся в модуле общения.              |
| Команда видит изменения в работе            | При настроенном обновлении списка новая заявка или изменённый статус появляется у сотрудников, которые уже открыли этот раздел. |

## Два сотрудника смотрят заявки

Один администратор меняет данные заявки. Другому, у которого список уже открыт, приходит событие об изменении. Интерфейс запрашивает актуальные данные с учётом его доступа.

Нужно подключить обновления к конкретному списку или экрану. Событие не предоставляет доступ к чужим данным: интерфейс должен заново получить разрешённые записи. Сообщение на почту — отдельный сценарий уведомлений.

## Соберите нужные бизнесу числа в своём проекте

Определите показатели, по которым следите за работой: количество заявок, заказов или другой результат. Модуль хранит числовые значения и позволяет показывать их в интерфейсе.

Чтобы решить, чем заняться дальше, владельцу нужны конкретные числа. Например, сколько заявок пришло и сколько заказов оформлено. У разных проектов показатели различаются, поэтому сначала нужно определить, что считать и откуда получать данные.

| Заголовок                             | Содержание                                                                                                                 |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Показатели соответствуют вашей работе | Выберите нужные числа и их названия. Для школы это могут быть заявки и заказы, для сервиса — количество выполненных задач. |
| Числа видны в рабочем интерфейсе      | Разместите значения в панели проекта. Источник, период и способ обновления задаются для каждого показателя.                |

## Добавляйте разделы с содержимым вашего бизнеса

У проекта могут быть отдельная страница запуска, сезонное предложение или блок с особыми условиями. Модуль Startup хранит содержимое таких разделов и предоставляет место для их представлений.

Не вся информация о бизнесе относится к товару, статье или заявке. Например, описание набора в новую школу и условия первого потока нужны на странице запуска. Для такого содержимого есть отдельные блоки проекта.

| Заголовок                              | Содержание                                                                                                                                     |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Особое предложение получает своё место | Добавьте текст и материалы запуска, которые не нужно оформлять как отдельный товар или статью.                                                 |
| Раздел можно доработать под задачу     | Используйте существующий вариант блока или добавьте новый в коде проекта. Содержимое можно редактировать через административное представление. |

## Страница первого набора в школу

Школа открывает первый поток. Помимо каталога ей нужны рассказ о формате, условия участия и обращение основателя. Эти сведения можно собрать в отдельном разделе запуска.

Startup — модуль содержимого, а не готовая система для любой отрасли. Если нужны бронирования, доставка или особые расчёты, сначала определяют данные и правила, затем дорабатывают подходящий модуль или создают новый.
