# AI Chat website

## Objective and visitor paths

Explain AI Chat as a distinct service and make the intended agent interaction understandable. A visitor must be able to distinguish service use from downloading the separate Code Framework. No verified public service URL or final external launch has been supplied.

The intended paths are agent discovery, registration/access, chat, and support. Their public availability remains a delivery gate.

## Design constraints

Agent identity, permitted use, knowledge limits, access allowance and interaction outcome must be visible. The intended flow needs distinct access-denied, exhausted-allowance, pending, answer, refusal, failure and support states. A failed request must not imply a successful answer or successful payment.

Mobile and keyboard users need the same access to agent selection, question entry and error recovery. Detailed page composition and product-specific asset selection remain review work; no new visual identity is selected by this restoration.
