## Connect the capability to its presentation.

For a token purchase, RBAC owns the current account and authorized actions. Ecommerce owns the product and order; Billing owns the payment records. The domain Widget passes rendered content into its exact linked Website Builder Widget. Host assembles the saved instances into a page.

## Четыре модели — понятная структура общения

Представьте школу с авторами и помощником. Профиль отвечает на вопрос «кто», чат — «где общаемся», ветка — «о чём», сообщение — «что сказано». Связи соединяют эти записи.

| Модель         | Пример и назначение                                                                                             |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| Profile · кто  | Дарья или помощник школы. Имя, описание и связанные материалы представляют человека или помощника в интерфейсе. |
| Chat · где     | Переписка по проекту. Чат объединяет сообщения и тематические ветки.                                            |
| Thread · о чём | «Обратная связь о лендинге». Отдельная тема со своей историей внутри чата.                                      |
| Message · что  | Вопрос, ответ или сообщение с файлом. Связи указывают автора, ветку и вложения.                                 |

## Что ещё есть в Social

Всего в модуле девять моделей. Дополнительные модели помогают настроить данные профиля, инструкции помощника и представление.

| Модель        | Для чего нужна                                                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Skill         | Повторно используемые инструкции для ИИ. Навык связан с профилем; в AI Chat явная команда /skill-slug включает подключённый навык для запроса. Само выполнение организует сценарий AI Chat.          |
| Attribute     | Типизированное значение профиля: строка, число, дата или логический признак. Например, направление работы эксперта.                                                                                  |
| Attribute Key | Описание такого поля: название, тип, префикс и суффикс. Помогает показывать дополнительные данные с понятными подписями.                                                                             |
| Action        | Запись события с данными и сроком действия. В AI Chat может хранить подготовленное представление работы помощника — например, обращения к знаниям. Правила выполнения остаются в управляющем модуле. |
| Widget        | Блоки для показа профилей и авторов. Они соединяют данные Social с оформлением страницы; авторизация переписки остаётся в RBAC.                                                                      |

## Как это выглядит в интерфейсе

В коде есть представления для карточки и страницы автора, списка его статей, навигации по веткам и рабочего окна переписки. Пример выше показывает возможное оформление; ссылки на рабочие компоненты собраны в конце страницы.

| Компонент       | Что показывает                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------ |
| Карточка автора | Имя, аватар или инициалы, описание, количество связанных статей и продуктов.                                       |
| Страница автора | Публичную информацию об авторе и его материалы. Публичный профиль не раскрывает настройки ИИ и владельца аккаунта. |
| Список веток    | Темы и документы с выбранным пунктом, чтобы возвращаться к нужной работе.                                          |
| Окно переписки  | Заголовок ветки, сообщения и поле ввода. Для документного режима предусмотрены области чата и документа.           |

## Добавляйте возможности по мере роста продукта

Social отвечает за социальные записи и связи. Остальные модули дополняют конкретный сценарий — их не нужно подключать все сразу.

| Модуль       | Что добавляет                                                                                                  |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| RBAC         | Аккаунт, текущего пользователя и проверки доступа к переписке. Аккаунт и публичный профиль — разные записи.    |
| File Storage | Аватары и вложения. Social связывает файл с профилем или сообщением.                                           |
| Blog         | Статьи автора. Связь профиля со статьёй формирует список его материалов.                                       |
| Knowledge    | Источники для ИИ-помощника. В обычном AI Chat поиск по ним включается через @knowledge.                        |
| Ecommerce    | Продукты, связанные с автором или веткой. Для заказов и оплаты дополнительно используются Ecommerce и Billing. |

## От сценария к первой версии

Начните с одного действия, которое нужно вашему пользователю. Остальные возможности можно добавить, когда появится необходимость.

| Шаг                    | Что сделать                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Выберите задачу        | Например: участник открывает профиль эксперта и задаёт вопрос по своему проекту.                                         |
| Определите доступ      | Решите, что видно гостю, какие действия требуют входа и кто может читать конкретную переписку.                           |
| Подготовьте интерфейс  | Используйте профили, ветки и сообщения. Подключите только нужные материалы, файлы или продукты.                          |
| Проверьте путь целиком | Откройте профиль, начните разговор, вернитесь к истории. Проверьте доступ из другого аккаунта и отображение на телефоне. |

| С чем связан      | RBAC проверяет пользователя и доступ к переписке. Knowledge возвращает разрешённые знания, а связи профиля с Blog показывают статьи автора. Аккаунт и публичный профиль — разные записи. |
| Пример применения | В сообществе участник открывает профиль автора и начинает переписку. Проверьте, что чужая личная ветка недоступна, а публичные материалы видны посетителям.                              |
