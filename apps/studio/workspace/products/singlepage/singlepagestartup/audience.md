# Аудитория

## Сегменты и ситуации

Основная аудитория Code Framework — предприниматели и создатели цифровых продуктов, которым нужны сайт или приложение со своими данными и правилами. Ситуации объединены в сегмент `makers`: человек выбирает функции для своего бизнеса, поручает изменения ИИ-агенту и проверяет результат.

| Ситуация                                                        | Что приводит к выбору фреймворка                                                                                                        |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Новый продукт или действующая услуга впервые выходят в интернет | Нужны описание, статьи, каталог и способ получить заявку или заказ. В дальнейшем сайт должен развиваться вместе с бизнесом.             |
| Создатель разрабатывает веб-сервис с ИИ-агентом                 | Регистрация, права доступа, оплата и данные нужны вместе с собственной функцией. Готовые модули дают агенту исходный код для доработки. |
| Существующий конструктор ограничивает нужный процесс            | Требуется изменить обработку заказа, доступ к материалам, взаимодействие с другим сервисом или связь контента с продуктами.             |

В небольшой компании владелец может одновременно выбирать продукт, пользоваться им и оплачивать инфраструктуру. При участии разработчика он отвечает за реализацию и обслуживание, а предприниматель — за условия своего предложения. `developer-agents` — путь выбора по поручению человека: агент изучает исходный код и объясняет, подходит ли он задаче.

## Потребности и ожидаемый результат

Предпринимателю нужен работающий путь клиента: найти предложение, понять условия, оставить обращение или купить. Поэтому состав фреймворка объясняется через страницы, каталог, формы, оплату и дальнейшую обработку. Для создателя приложения на первом месте возможность изменить логику и сохранить контроль над данными и размещением.

Уже доступные альтернативы задают уровень сравнения. [Тильда](https://help.tilda.cc/online-store) предлагает каталог, корзину, оплату и личный кабинет покупателя. [Open SaaS](https://opensaas.sh/) объединяет авторизацию, платежи, блог и инструкции для разработки с ИИ. Поэтому наличие входа и оплаты само по себе не объясняет выбор SPS. Его соответствие задаче проявляется в связях: статья относится к продукту, заказ — к покупателю и платежу, а агент может изменить серверное правило вместе с интерфейсом.

Из сравнения следует практический приоритет: Code Framework уместен, когда бизнесу нужны несколько связанных функций и дальнейшие изменения. Для одной простой страницы готовый конструктор может требовать меньше технической работы. Это вывод по составу предложений и способу их использования.

## Критерии выбора и возражения

| Критерий или вероятный вопрос                  | Ответ Code Framework                                                                                                                                                                                                                                                       |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| «Смогу ли я разобраться без опыта разработки?» | Первое знакомство проходит в демонстрации AI Chat: человек вводит сведения своего бизнеса и работает с ними в чате. При создании собственного приложения агент меняет код, а владелец проверяет действия клиента. Для настройки и обслуживания можно привлечь специалиста. |
| «Какие задачи бизнеса уже поддерживаются?»     | Страницы, каталог, статьи, формы, пользователи, заказы и платежи связаны в одном проекте. Чаты, знания и уведомления добавляют способы работы с клиентом. Состав подбирается под конкретный процесс.                                                                       |
| «Что именно бесплатно?»                        | Исходный код по MIT. Сервер, домен, ИИ-инструмент и внешние сервисы оплачиваются отдельно. Помощь по фреймворку предоставляется по возможности.                                                                                                                            |
| «Смогу ли я сменить исполнителя или сервер?»   | Приложение хранится в собственном репозитории и разворачивается на выбранном сервере. Другой специалист может продолжить работу с тем же кодом и данными.                                                                                                                  |
| «Что делать, если готового правила нет?»       | Агент или разработчик добавляет его в проект. Например, ограничение количества товаров проверяется в обработке заказа и объясняется покупателю в интерфейсе.                                                                                                               |
| «Что происходит после запуска?»                | Владелец продолжает менять продукт, публиковать материалы и обновлять приложение. Доступы, резервное копирование и инфраструктура находятся в его управлении либо передаются техническому специалисту.                                                                     |

Эти вопросы выведены из условий SPS и сравнения способов создания сайта; это вероятные возражения при выборе, а не цитаты клиентов. [Сравнение конкурентов](/?path=/story/workspace-10-products-singlepage-singlepagestartup--competitors) раскрывает различия предложений.

## Выводы для коммуникации

Для предпринимателя главное сообщение — «Сайт и цифровые инструменты для вашего бизнеса: каталог, заявки, заказы и материалы с возможностью менять правила». Пример должен соединять предложение и действие клиента: статья об услуге, форма обращения и сохранённая заявка. По нему человек оценивает, какие части нужны его бизнесу.

Для создателя веб-сервиса главное сообщение — «Используйте готовые бизнес-модули и поручайте ИИ доработку своего продукта». Ему нужен пример изменения, затрагивающего данные, сервер и интерфейс, а затем доступ к исходному коду.

Общее первое действие — **попробовать в AI Chat на данных своего бизнеса**. Демонстрация помогает понять способ работы до установки окружения. GitHub — следующий путь для разработки собственного приложения и дополнительная точка входа для технической аудитории. При продвижении партнёрского размещения показывается его будущий результат: подключить сервер и запустить подготовленный продукт из чата.
