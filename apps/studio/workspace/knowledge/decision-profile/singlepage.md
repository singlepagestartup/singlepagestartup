# Decision profile

## Business-model classification

| Dimension             | Current classification                                                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Primary model         | Founder-funded reusable developer framework distributed free of charge                                                                       |
| Secondary model       | Separate AI-agent demonstration service used as showcase and acquisition bridge; may later sell service access                               |
| User/decision-maker   | Accountable developer choosing architecture for a new multi-feature product                                                                  |
| Payer                 | None for the framework; a future demonstration-service user may pay for service access                                                       |
| Value unit            | Framework setup plus one relevant capability check; adoption requires repeat use or a retain decision                                        |
| Money/capacity        | Founder time and money fund the framework; service subsidy and service revenue stay separate                                                 |
| Material dependencies | License publication, setup consistency, showcase readiness, attribution, privacy/security, support capacity, and external developer behavior |

The framework and demonstration service form one acquisition system but never one evidence or revenue ledger.

## Viability and evidence rules

- Do not interpret repository attention, stars, service traffic, payments, subsidy, runtime, or load as framework adoption.
- Do not launch the evaluation path until the effective license, prerequisites, setup instructions, pinned version, and claim boundaries agree.
- Stop or pause service access when provider cost, authority, privacy, security, incident recovery, or founder capacity cannot be bounded.
- External successful use requires an attributable independent developer setup and capability result; adoption requires repeat use or a retain decision.
- Every primary artifact stays within 1,400 words and contains one current decision per topic. Evidence and Assets remain reference registers.
