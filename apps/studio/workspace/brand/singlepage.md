# Brand

## Decision status

| Field                 | Current value                                        |

| Current product       | Code Framework                                       |

Brand describes what should form in the audience's mind. The separate Design
artifact owns visual execution.

## Intended perception

SinglePageStartup should be understood as a project that creates **inspectable, deliberate tools for accountable developers building multi-feature web products**. Its current primary product is Code Framework, a reusable code foundation. The name SinglePageStartup belongs to the overall project and brand rather than to that product alone.

The audience should remember three ideas:

1. several recurring foundations can be evaluated together;
2. the developer can inspect the code, prerequisites, evidence, and limits before committing;
3. AI may assist the work, but a human remains responsible for architecture, permissions, data, testing, deployment, and acceptance.

The character is precise, calm, candid, modular, and accountable. It is not autonomous-AI theatre, enterprise authority, startup-speed spectacle, or a promise that included directories equal working integration.

## Meaning and message hierarchy

| Level              | Current message                                                                                                                                          |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Audience situation | A developer is about to choose architecture for a product that needs several recurring foundations                                                       |
| Decision barrier   | Starters, generators, prior code, composed services, and AI output are difficult to compare for coherent fit, rights, prerequisites, and maintainability |
| Primary meaning    | Inspect the foundations before the architecture is fixed                                                                                                 |
| Promise            | Evaluate one pinned Code Framework release for one named product need through explicit inventory, rights, prerequisites, setup, and one capability check |
| Proof available    | A public repository snapshot, documented module inventory, releases, current license state, and explicit limitations                                     |
| Proof missing      | Independent setup, successful use, repeat use, adoption, time saving, reliability, compatibility, or production outcomes                                 |
| Primary action     | Evaluate Code Framework on GitHub                                                                                                                        |
| Secondary action   | See the demonstration service only after its named behavior and framework attribution are verified                                                       |

The demonstration service is a showcase and acquisition bridge. Service traffic, payments, subsidized use, runtime, or load never become framework adoption evidence without a separate developer evaluation path.

### Objections

- **“This looks like more inherited complexity.”** Show the pinned inventory, prerequisites, limitations, and exit path; do not claim universal fit.
- **“AI can generate the same thing.”** Compare inspectability, human accountability, and coherent foundations without claiming better AI output.
- **“Is it production-ready and supported?”** State the current evidence and best-effort founder boundary; do not imply readiness or an SLA.
- **“Can I use it commercially?”** State the effective published license. Do not describe the current repository as MIT-licensed until the selected change is published.

## Voice and language

- Use short, direct sentences and concrete nouns: version, prerequisite, setup, capability, limitation, evidence, owner, and decision.
- Separate `observed`, `founder-reported`, `intended`, `missing`, and `approved` when the distinction affects trust.
- Lead with the developer's decision, then the bounded promise, proof, limits, and action.
- Use the exact brand name **SinglePageStartup** and product name **Code Framework**. Use **Code Framework by SinglePageStartup** when both must be clear. Do not abbreviate or split the brand name into three words.
- Prefer “evaluate,” “inspect,” “verify,” and “retain” over “revolutionize,” “effortless,” “complete,” or “AI-powered.”

### Do and do not

| Do                                                                | Do not                                    |
| ----------------------------------------------------------------- | ----------------------------------------- |
| “Evaluate the foundations for one named product.”                 | “Everything your startup needs.”          |
| “Current proof is limited to the repository and declared checks.” | “Production-ready and proven.”            |
| “The developer owns permissions, review, tests, and acceptance.”  | “Let AI launch the product autonomously.” |
| “Founder help is best effort when capacity permits.”              | “Dedicated support whenever you need it.” |

Prohibited claims include current MIT licensing, complete integration, easy or zero-configuration setup, security/compliance, broad compatibility, time or money saved, customers, traction, adoption, guaranteed availability/support, or demonstration-service activity presented as framework success.

## Governance

- Strategy owns audience, offer, commercial focus, acquisition route, and experiment.
- Brand owns intended perception, meaning hierarchy, voice, naming, and claim boundaries.
- Design translates approved Brand into reusable visual rules without changing its meaning.
- Website owns page journey, final copy, navigation, forms, states, and post-conversion behavior.
- Marketing Creative owns only formats selected by Strategy.
- Material sources stay with their owning claims; Assets owns file rights and lifecycle. Generated imagery is never proof.

Any change to audience, promise, public name, proof boundary, or primary action requires Brand review. Visual or format changes that preserve these decisions remain in Design, Website, or Marketing Creative.
